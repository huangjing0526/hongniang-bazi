## 任务一：px → rem，让系统字号设置真的生效

### 现在的行为

- `index.html` 里 **154 处 `font-size`**，全是硬编码 `px`，其中 **103 处 ≤12px**
- 基本排盘页可见文字节点：15px 96 个、12px 63 个、11px 53 个——**11–12px 占了一半**
- 全站 `rem` 用量为 **0**（`grep -c '[0-9]rem'` = 0）
- `index.html:5` 的 viewport 是
  `width=device-width, initial-scale=1.0, maximum-scale=1.0, user-scalable=no`

三个放大通道全堵着：系统字号设置对 px 无效；双指缩放被显式关掉；页面缩放能用但会
把双栏断点顶回单栏。老师在 iPad 上想把神煞看清楚，没有任何办法。

### 要做成什么

**1）放开缩放。** `index.html:5` 只留 `width=device-width, initial-scale=1.0`，
删掉 `maximum-scale=1.0, user-scalable=no`。这一步零风险，先做。

**2）不要设 `html { font-size }`。** 既不要 `62.5%` 也不要 `16px`。
设了就等于把系统字号设置又架空一次，本轮的意义全没了——保持继承浏览器默认值。

**3）154 处 `font-size` 按 `值 ÷ 16` 机械换算成 `rem`，1:1，不做视觉合并。**
照抄这张表，别自己凑整：

| px | rem | px | rem |
|---|---|---|---|
| 9 | 0.5625 | 14 | 0.875 |
| 10 | 0.625 | 15 | 0.9375 |
| 10.5 | 0.65625 | 16 | 1 |
| 11 | 0.6875 | 17 | 1.0625 |
| 11.5 | 0.71875 | 18 | 1.125 |
| 12 | 0.75 | 19 | 1.1875 |
| 13 | 0.8125 | 23 | 1.4375 |
| 13.5 | 0.84375 | 其余 | `x / 16`，保留 5 位小数 |

10.5 / 11.5 / 13.5 这几个碎值**保留原样换算**，不要顺手并到相邻档位——那是重新
设计，会破坏「像素级一致」这条硬约束。

**4）24 处固定 `height` / `min-height` 里，凡是装文字的一并换 `rem`**：
按钮、神煞 chip、tab 条、干支下拉、输入框。纯装饰的（分隔线、印章、图标块）留 `px`。
字号变大而容器高度锁死 px，结果就是夹字——这是本轮最容易漏的一处。

**5）`line-height` 现在全是无单位值（px 行高 0 处，已核），保持无单位，别动。**

### 明确不要换成 rem 的

`border-width`、`box-shadow`、`border-radius`、`letter-spacing`、
`padding` / `margin` / `gap`、media query 里的 px。

前几项换了会让放大时整体膨胀、间距失控；media query 留 px 是本轮的**明确取舍**：
字号放大后断点不跟着走。这个取舍要写进回执，将来若要改成 rem 断点单开一轮。

### 边界条件（验收逐条点）

| 场景 | 期望 |
|---|---|
| 浏览器默认字号（16px），1440px 宽 | 与改前**像素级一致** |
| 浏览器默认字号，1024px 宽 | 与改前一致（叠加任务二的新布局） |
| 浏览器默认字号，375px 宽 | 与改前**像素级一致** |
| 浏览器字号调到 20px（125%） | 文字同比变大；神煞 chip / tab 条 / 干支下拉 / 提交按钮**不夹字、不截断** |
| 浏览器字号调到 24px（150%） | 同上。允许换行变多，**不允许文字被裁** |
| iPad 双指放大 | 能放大（改前放不了） |
| **字号 150% + 1024px 宽** | 双栏不塌、不横向溢出——**这是两条任务的交界，必须实测** |

## 任务二：双栏断点降到 1024px，右栏改流体宽

### 现在的行为

双栏（盘在左、390px 裁定栏在右）只在 `@media (min-width: 1080px)` 生效。实测：

| 视口宽 | `#tab-chart` 布局 | 裁定表单起始 y | 页面总高 | 卷宗实宽 |
|---|---|---|---|---|
| 900px | 单栏 | 1122 | 1800 | 740 |
| **1024px** | **单栏** | **1122** | **1800** | **740** |
| 1079px | 单栏 | 1121 | 1799 | 740 |
| 1080px | 双栏 642+390 | **179** | 1270 | 1080 |
| 1440px | 双栏 662+390 | 179 | 1243 | 1100 |

断崖卡在 1080px 这一格。iPad Pro 横屏（1024×768）上裁定表单在 y=1122，**要往下滚
一屏半才够得着**——而核盘就是「看一眼盘、填一条裁定」来回对照的动作。这个区间里
卷宗还锁死 740px，1024px 视口白白空掉 284px。

### 要做成什么

- `@media (min-width: 1080px)` 整块的断点改成 **1024px**
- `grid-template-columns: minmax(0, 1fr) 390px`
  → `minmax(0, 1fr) minmax(340px, 390px)`
  （现在 642+390+16 间距+32 内边距=1080 刚好塞满，不收窄右栏降不下来）
- `.sheet` 的 `max-width: 1100px` 随该块一起降到 1024 生效；
  **760–1023 那档的 `max-width: 740px` 不动**
- `@media (min-width: 1080px) and (max-height: 640px)` 这条矮屏特例：跟着降到
  1024，或者明确不降——**两种都接受，但要在回执里说明为什么**

### 边界条件（验收逐条点）

| 场景 | 期望 |
|---|---|
| 1023px | 单栏，与改前的 1023px 一致 |
| 1024px | 双栏，**裁定表单落在首屏内**（起始 y < 视口高） |
| 1024px 下右栏内容 | 四排干支下拉不错位换行；神煞浮层不越界；理由输入框不溢出 |
| iPad Pro 横屏 1024×768 | 盘与裁定表单同屏可见，核一条盘不用滚 |
| 1440px | 与改前**完全一致**（右栏仍取到 390px 上限） |
| 1024×640 矮屏 | 按你对特例的处理，结果自洽、不出现横向滚动条 |
| 字号 150% + 1024px | 见任务一最后一行，同一条 |
