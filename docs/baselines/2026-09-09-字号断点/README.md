# 像素回归基线 · 字号与断点任务

配套任务书：`docs/2026-09-09-任务书-antigravity-字号与断点.md`

这组图是在 **`a37b36b`（动代码之前）** 截的，代表「改造前的样子」。
任务的硬约束是**默认字号下不许有任何视觉变化**，靠肉眼判不出来，所以用它来卡。

## 六张图分别是什么

| 文件 | 视口 | 看什么 |
|---|---|---|
| `1-375x812.png` | 375×812 | 手机窄屏，神煞 chip 换行 |
| `2-1023x900.png` | 1023×900 | 断点**下沿**：改后这张仍应是单栏，且与基线一致 |
| `3-1024x768.png` | 1024×768 | iPad Pro 横屏，**改后这张应该变成双栏**，与基线不同是预期的 |
| `4-1080x900.png` | 1080×900 | 原断点位置，改前改后都该是双栏 |
| `5-1440x900.png` | 1440×900 | 宽屏，右栏取满 390px，改后应与基线**完全一致** |
| `6-1024x768-字号150.png` | 1024×768，浏览器默认字号 24px | 改造前的坏样子：字号调到 150% 只有极少数继承 body 的文字变了，神煞和裁定表单纹丝不动。**改后这张应该整体变大**，所以它是「反向基线」——跟它一样才是没修好 |

所以判读方式不是「六张全都要一致」：

- **必须一致**：`1`、`2`、`5`
- **必须不同**：`3`（要变双栏）、`6`（要真的变大）
- `4` 应该一致（1080 本来就是双栏，右栏仍取 390px 上限）

## 怎么再截一组

```bash
# 1. 装 playwright 到仓库外（本仓是零依赖的，别写进 package.json）
mkdir -p /tmp/pw && cd /tmp/pw && npm init -y
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm i playwright     # 用系统已装的 Chrome，不下内核

# 2. 起服务，DB_PATH 指到临时库，别碰 data/
cd <仓库根>
DB_PATH=/tmp/baseline.sqlite PORT=8099 node cloud/server.mjs &

# 3. 截图
PLAYWRIGHT_DIR=/tmp/pw node "docs/baselines/2026-09-09-字号断点/capture.mjs" /tmp/after 8099
```

每张都走同一条固定路径：登记「基线」→ 载入样盘库 → 停在第 1 条的「基本排盘」页，整页截。

## 怎么比

```bash
magick compare -metric AE 基线.png /tmp/after/同名.png null:
```

输出 `0 (0)` 就是零差异。**这组基线自比过两轮，六张全是 0**，所以「像素级一致」
是个能达到的标准，不是口号。

## ⚠️ 先跑对照组，再下结论（2026-09-10 补）

**基线图会随浏览器版本失效。** 图是用系统 Chrome 截的，Chrome 一更新，字体抗锯齿
就可能整体漂移一两个色阶——代码一个字没动，比出来也是几百个像素的差异。

2026-09-10 验收字号断点那轮就撞上了：拿改动后的代码比基线，四张「必须 0 差异」的
图全是 130–147 像素，差点判成回归。用 worktree 把**改动前**的代码单独跑一遍才发现，
它比出来是同样的 147 / 130 / 142 / 135 ——一模一样，跟改动无关。

所以看到非零差异时，先问一句「未改动的代码比出来是几」：

```bash
# 在仓库外开一个改动前的 worktree（不碰你工作区里未提交的改动）
git worktree add /tmp/wt-before <改动前的 commit>
cp -R engine/node_modules/lunar-javascript /tmp/wt-before/engine/node_modules/   # 构建要用
cd /tmp/wt-before && node scripts/build.mjs
DB_PATH=/tmp/before.sqlite PORT=8098 node cloud/server.mjs &

# 同一轮里截两组，比这两组，而不是比昨天的基线
PLAYWRIGHT_DIR=/tmp/pw node "docs/baselines/2026-09-09-字号断点/capture.mjs" /tmp/control 8098
PLAYWRIGHT_DIR=/tmp/pw node "docs/baselines/2026-09-09-字号断点/capture.mjs" /tmp/after   8099
magick compare -metric AE /tmp/control/同名.png /tmp/after/同名.png null:

git worktree remove --force /tmp/wt-before    # 用完删掉
```

**判据是「同环境下 改前 vs 改后」，仓库里这组基线只是个参照物。**
两个数一致 = 环境漂移，可以放过；只有改后那组偏离对照组，才是真回归。

顺带一个量级参考：环境漂移长这样——差异全是**孤立的单像素**（连通块 1×1），
峰值误差约 1 个色阶（`magick compare -metric PAE` 给 257/65535）。真的布局改动
是成片的，量级在十万以上。用 `-metric PAE` 和连通块分析能一眼分开这两者。

## ⚠️ 每组截两次，落单的那次丢掉（2026-09-10 补）

还有第二种假差异：**对着刚启动的服务跑的第一次截图，`.sheet` 底部那道 38px 柔和
投影会渲染成另一个样子**，约一万个像素、峰值误差 9%——比抗锯齿噪声大得多，很像
真的回归。

2026-09-10 修出生地控件时撞上：`3-1024x768` 比出 11634 像素差异。四组交叉比对才
定案——

| | |
|---|---|
| 第一次对照组 vs 其余三组 | 11634（对每一组都是同一个数） |
| 其余三组（对照第二次、改后两次）互比 | **全 0** |

落单的是**第一次对照截图**，不是改动。

所以判读规则是：**每组截两次**（`/tmp/control`、`/tmp/control2`），先看组内自比。
组内自比不为 0，就说明这组里有一张是冷启动那次；把它丢掉，用稳定态那张去比。
四组里三组互相一致、一组跟谁都差同一个数 = 那一组是异类，不是回归。

差异全落在页面最底 90px（`.sheet` 投影带）而 DOM 布局逐项相同时，基本可以直接
判定是这个伪影：布局真变了，页高、sheet 高、页脚位置至少会动一样。

## 两处被中和掉的东西

截图前脚本会注入一小段 CSS（基线与复测两边同样处理）：

- `body::before` —— `position: fixed` 的装饰渐变。整页截图时它的合成位置不稳定，
  同一份代码连截两次都能差 12 万像素，不中和就没法比
- `#sync-status` —— 「已同步 N 条」，文案随同步时机变

代价是这两处的样式**不在像素比对的覆盖范围内**。本轮任务不碰它们，改到了要在回执里说。
