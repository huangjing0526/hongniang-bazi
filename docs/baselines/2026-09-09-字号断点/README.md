## 六张图分别是什么

| 文件 | 视口 | 看什么 |
|---|---|---|
| `1-375x812.png` | 375×812 | 手机窄屏，神煞 chip 换行 |
| `2-1023x900.png` | 1023×900 | 断点**下沿**：改后这张仍应是单栏，且与基线一致 |
| `3-1024x768.png` | 1024×768 | iPad Pro 横屏，**改后这张应该变成双栏**，与基线不同是预期的 |
| `4-1080x900.png` | 1080×900 | 原断点位置，改前改后都该是双栏 |
| `5-1440x900.png` | 1440×900 | 宽屏，右栏取满 390px，改后应与基线**完全一致** |
| `6-1024x768-字号150.png` | 1024×768，浏览器默认字号 24px | 改造前的坏样子：字号调到 150% 只有极少数继承 body 的文字变了，神煞和裁定表单纹丝不动。**改后这张应该整体变大**，所以它是「反向基线」——跟它一样才是没修好 |

所以判读方式不是「六张全都要一致」：

- **必须一致**：`1`、`2`、`5`
- **必须不同**：`3`（要变双栏）、`6`（要真的变大）
- `4` 应该一致（1080 本来就是双栏，右栏仍取 390px 上限）

## 怎么再截一组

```bash
# 1. 装 playwright 到仓库外（本仓是零依赖的，别写进 package.json）
mkdir -p /tmp/pw && cd /tmp/pw && npm init -y
PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm i playwright     # 用系统已装的 Chrome，不下内核

# 2. 起服务，DB_PATH 指到临时库，别碰 data/
cd <仓库根>
DB_PATH=/tmp/baseline.sqlite PORT=8099 node cloud/server.mjs &

# 3. 截图
PLAYWRIGHT_DIR=/tmp/pw node "docs/baselines/2026-09-09-字号断点/capture.mjs" /tmp/after 8099
```

每张都走同一条固定路径：登记「基线」→ 载入样盘库 → 停在第 1 条的「基本排盘」页，整页截。

## 怎么比

```bash
magick compare -metric AE 基线.png /tmp/after/同名.png null:
```

输出 `0 (0)` 就是零差异。**这组基线自比过两轮，六张全是 0**，所以「像素级一致」
是个能达到的标准，不是口号——出现非零差异就是真的改到东西了，别当成噪声放过。

## 两处被中和掉的东西

截图前脚本会注入一小段 CSS（基线与复测两边同样处理）：

- `body::before` —— `position: fixed` 的装饰渐变。整页截图时它的合成位置不稳定，
  同一份代码连截两次都能差 12 万像素，不中和就没法比
- `#sync-status` —— 「已同步 N 条」，文案随同步时机变

代价是这两处的样式**不在像素比对的覆盖范围内**。本轮任务不碰它们，改到了要在回执里说。
