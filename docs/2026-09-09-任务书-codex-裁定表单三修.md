## 任务一（🔴 最重要）：换命例时裁定表单不清空，会把 A 的答案记到 B 头上

### 现在的行为

`resetVerdictForm()` 全项目只在 `submitVerdict()` 里调过一次（`app.js:2562`）。
换命例的链路是：

```
stepCase / nextUnjudgedCase / selectBatchCase
  → loadCaseToChart          (app.js:2462)
  → applyCaseToInput         (app.js:2415，只动 state.input，不碰裁定表单)
  → runCompute → renderAll
  → renderVerdictForm        (app.js:1447，只改「已裁定 N 条」那行提示)
```

全程没有一个字段被清。所以：老师给 A 盘勾了「时柱分歧」、选了「客户自报」、填了
干支，没提交就点「下一条」，这些值原封不动挂到了 B 盘上。他接着补一句理由点提交，
**A 的答案就落到 B 的 `chart_id` 上了**——正是这份工具唯一要收的东西被写坏。

批量核盘（30 条连着翻）是主推流程，这条路径必踩。

### 要做成什么

不是简单清空，而是**按命例存草稿**：老师核到一半跑去翻万年历、或者翻回上一条再翻
回来，他填过的东西还在。清空反而制造新的挫败。

### 实现建议（不强制照抄，但边界条件必须都覆盖）

关键在于**只设一个钩子**，别在每个换盘的调用点各写一遍——`apply12DigitInput`、
`clearQuickInput`、`applyBatchInput` 这些路径不走 `loadCaseToChart`，逐个挂必漏。

推荐挂在 `renderVerdictForm()` 里，因为 `renderAll()` 每次都会调它：

```js
// 模块级：上一次渲染时表单归属于哪条命例。不是从 state 现算——
// apply12DigitInput 会先 upsertCaseFromInput 换掉 activeCaseIndex 再 runCompute，
// 那时表单里装的还是上一条的答案，只有记着的旧 id 才是它真正的归属。
let verdictFormCaseId = null;
const verdictDrafts = new Map();   // caseId → 表单快照
```

`renderVerdictForm()` 开头：

```
const nowId = activeCaseId();
if (verdictFormCaseId !== null && verdictFormCaseId !== nowId) {
  收集当前表单 → 非空则存进 verdictDrafts[verdictFormCaseId]，空则删除该键
  resetVerdictForm()
  verdictDrafts 里有 nowId 的草稿 → 回填，并 toast「已取回这条盘上次没写完的裁定」
}
verdictFormCaseId = nowId;
```

配套两个小函数，字段清单与 `submitVerdict` / `resetVerdictForm` 读写的完全一致：

- `captureVerdictDraft()` → `{ consistent, pillars:{year|month|day|time:{gan,zhi}},
  checkedPillars, timeSource, school, schoolCustom, reason, shensha:[], shenshaNote }`
- `applyVerdictDraft(draft)` → 反向写回，并把有分歧的那几个 `#verdict-group-*`
  的 `display` 恢复（照 `onDisputedPillarToggle` 的做法，别自己另写一套显示逻辑）

「非空」的判断：勾了「与我们一致」、勾了任一柱、选了时间来源、选了流派、写了理由、
勾了神煞异议、写了神煞备注——**任一为真即算有内容**。全空就别存，否则
`verdictDrafts` 里全是空壳，回填时还要 toast 一句，反而吵。

### 边界条件（验收会逐条点）

| 场景 | 期望 |
|---|---|
| A 填一半 → 点「下一条」到 B | B 的表单是空的；toast 不提示（B 没草稿） |
| 接上条，再点「上一条」回 A | A 的答案原样回来，toast 提示取回了草稿 |
| A 填一半 → 切「万年历」tab → 切回「基本排盘」 | **表单不动**（caseId 没变，不该触发存取） |
| A 填一半 → 拨真太阳时 / 夏令时 / 子时开关 | **表单不动**（同上，caseId 没变） |
| A 填一半 → 夏令时双盘里点另一个盘（`selectDualChart`） | **表单不动**（同一条命例的两种排法） |
| A 填一半 → 在快速录入敲一个新的 12 位数排盘 | 新盘表单为空；A 的草稿留着，翻回 A 能取回 |
| A 提交成功 | A 的草稿从 `verdictDrafts` 删掉（别让已提交的内容又被回填一次） |
| 在批量列表里删掉 A（`removeBatchCase`） | A 的草稿一并删掉 |
| 「清空重录」/「清空列表」把 activeCaseIndex 置 -1 | 表单清空，不报错 |

草稿**要不要持久化到 localStorage 由你定**：存了刷新不丢（与本项目"什么都存"的
一贯做法一致），键名照 `bazi_verdicts` 的风格取；不存也接受，但要在回执里说明理由。
若存，`clearAllVerdicts` 不要连草稿一起清——那是两件事。

## 任务二：提交类动作能连点，重复落库

### 现在的行为

全项目只有 `#register-submit-btn` 有 disabled 态（`app.js:798`）。

1. **「提交老师裁定」**（`submitVerdict`）是同步的，双击就是两次完整执行。
   更难看的是第二次的表现：第一次跑完 `resetVerdictForm()` 已把「时间来源」清空，
   第二次进来 `timeSourceEl` 为 null，于是**刚提交成功就弹一条朱红报错**
   「请选时间来源」并把那一栏标红。老师会以为自己提交失败。
2. **「解析并追加到列表」**（`applyBatchInput`，async，里面 `await whenCityDataReady()`）
   城市库还没好时连点两下，两次 await 都会返回，第二次虽有 id 去重兜着不会真的
   重复，但会多弹一条「这 N 条命例都已在列表中」的 toast，看着像出错。
3. **「载入样盘库」**（`loadSampleCases`，async，内部 await `applyBatchInput`）同上。

### 要做成什么

- 加一个通用的按钮忙碌态包装，别在三处各写一遍。形如：

```js
/** 按钮跑完之前先禁掉：这三个动作都会落库，连点两下就是两条记录或两条自相矛盾的提示 */
async function withBusy(btn, label, fn) { ... }
```

  跑之前 `btn.disabled = true` 并把文案换成 `label`（如「提交中…」「解析中…」），
  `finally` 里恢复原文案与 disabled。原文案从 `btn.textContent` 现取，别写死。

- `submitVerdict` 额外加一层模块级 `isSubmittingVerdict` 标志兜底：按钮虽然禁了，
  但 `window.app.submitVerdict()` 是导出的，键盘/脚本仍能重入。
- `submitVerdict` 提交成功后，按钮文案短暂显示「✓ 已提交」约 1 秒再恢复。
  现在提交后表单一空、页面没别的变化，老师看不出到底成没成——那条
  「✓ 此盘已有 N 条裁定」的提示在表单上方，滚下来提交的人看不见。

### 不在本任务内

`exportVerdictsJson` 连点只是下载两个一模一样的文件，无害，**不要动**。
`submitRegister` 已经有 disabled 态了，**不要重写**。

## 任务三：神煞标签只能用鼠标点

### 现在的行为

`app.js:1416-1424` 把神煞渲染成裸 `<span onclick>`：无 `tabindex`、无 `role`、
无键盘处理。

```js
html += `<span class="${hasConfirm ? 'note' : ''}"
           onclick="window.app.showShenShaSource('${escapeHtml(pKey)}', ${sIdx})">
           ${escapeHtml(ss.name)}</span>`;
```

那 4 条带 `*` 的表源分歧（德秀贵人 / 福星贵人 / 学堂 / 羊刃）是试用说明里
**明确点名要收**的意见，而进入「对这条表源有异议」的唯一入口就藏在这个 span 后面。
键盘用户完全够不着。

### 要做成什么

1. 渲染成 `<button type="button" class="shensha-chip">`，Enter/Space 白拿，不必自己
   绑键盘事件。CSS 里把 `.shensha-list span` 的规则改挂到 `.shensha-list .shensha-chip`，
   并补上按钮默认样式的重置（`border:0; background:...; font:inherit; color:inherit;
   padding` 沿用现值）。`.shensha-empty` 保持 `<span>`——它不可点。
   顺带给 `.shensha-chip:focus-visible` 一个 `outline: 2px solid var(--cinnabar)`，
   照 `.alm-day:focus-visible` 那条的写法。
2. 把浮层（`#shensha-pop`）的键盘路径补完，否则只做了一半——键盘进得去出不来：
   - 打开时把焦点移进浮层（`.shensha-pop-close` 或卡片本身，卡片需 `tabindex="-1"`）
   - `Escape` 关闭
   - 关闭后焦点回到**触发它的那个 chip**（打开时记下 `document.activeElement`）
   - 浮层打开期间焦点不要跑到背后的页面上（简单做法：给卡片加 `role="dialog"`
     `aria-modal="true"`，并在 `keydown` 里拦 Tab 做循环；**不要引入 focus-trap 库**）

### 不在本任务内

其余 ARIA 缺口（`.tab-pane` 没有 `role="tabpanel"`、toast 没有 `aria-live`、
tab 不支持左右箭头）**不要顺手补**，那是另一条待排的任务。
