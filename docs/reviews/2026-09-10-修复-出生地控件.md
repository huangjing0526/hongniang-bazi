# 修复 · 出生地控件：手写路径与键盘路径

起因：Jing 反馈「地区控件筛选和手写很奇怪」，补一句「用户可能不知道怎么使用」。
后面这句点破了根因。

## 先说筛选：其实是好的

实测搜索排序没问题，歧义地名排得也对：

| 搜 | 第一条 |
|---|---|
| 朝阳 | 北京市 北京市 **朝阳区**（不是辽宁朝阳市） |
| 西安 | 陕西省 **西安市**（不是吉林辽源西安区） |
| 兰州 | 甘肃省 兰州市 |
| 浦东 | 上海市 上海市 浦东新区 |

拼音搜不到（`lanzhou` 无结果），但那是没做的功能，不是坏掉的功能，本轮不加。

## 坏的是输入这一侧，四条

### 1. 中文输入法每敲一个拼音字母就闪一次「没找到」

最可能就是「手写很奇怪」的本体。`handleSearch` 绑在 `input` 上，而 Chrome 在拼音
上屏之前照样派发 `input`（`isComposing: true`）。实测模拟输入法打「兰州」：

```
拼音「l」      → 面板开，红字「没找到「l」…」
拼音「la」     → 没找到「la」
…            （共 7 次）
拼音「lanzhou」→ 没找到「lanzhou」
上屏「兰州」    → 才出来 甘肃省 兰州市…
```

老师眼前先闪过 **7 次红字报错**才看到结果，每次还全表扫 3206 条。
改法：`if (e?.isComposing) return;`，并补听 `compositionend`——上屏那一下才真搜。

### 2. 唯一的使用说明被自己盖住了

搜索框 placeholder 写着「或直接搜：输入省、市或区县，如 兰州、朝阳」——
**这句话老师从来没见过**：placeholder 只在框为空时显示，而 `setValue()` 不管
选没选中都把完整地名填进去，从打开的第一秒起就是满的。
于是控件看起来只是「三个下拉 + 一个显示框」，能搜这件事无从得知。

更糟的是没落实出生地时：`app.js:926` 把解析不出的行直接换成哨兵
`UNKNOWN_CITY = '未知地（按标准时）'`（原词并不保留），这句**不是地名、没有搜索价值
的占位话**就被填进搜索框，恰好在老师最需要看见「可以直接搜」的时候盖住它。

### 3. 点进去打字会拼到旧地名后面

框里是「甘肃省 兰州市 城关区」，点一下光标停在点击处（实测第 11 位），
接着打「兰州」就变成 `甘肃省 兰州市 城关区兰州`，弹「没找到」。
老师得先自己全选删干净才能搜，而没有任何东西提示他要这么做。

### 4. 候选列表只认鼠标

条目是裸 `<div>`，无 `tabindex`、无 role，只挂了 `mousedown`。
按 ↓ 没有高亮，按 Enter 不但选不中，框里还会悄悄变回旧地名——
因为这个框在表单里，回车被当成提交了。用户以为选中了，其实没有。

## 改法

**搜索框恒为纯搜索框，不再兼职显示「当前选的是哪儿」**——那件事归三个下拉。

第一版我写的是「按名录认不认得这个名字来决定框里留不留字」，理由是「名录外的名字
不留就丢了」。`/simplify` 的高度审查把这个立论推翻了，复核属实：

- 解析不出的地名**根本没被保留**，`app.js:926` 直接换成 `UNKNOWN_CITY` 哨兵
- `getName()` 全仓零调用，`searchInput.value` 唯一的读取点是取查询词
- 真值在 `state.input.cityName` / `almanacState.cityName`，组件是受控的

所以那个框不是任何数据的家，「留字」纯粹是显示需求被塞进了输入控件。分支只是把
「恒定双重职责」改成「由数据决定是哪一重」，用户看不见判据，反而更隐蔽；而且
`handleSelect` 里无条件清空，同一条规则在隔壁分支被静默推翻。

删掉分支后更简单，也更对：出生地缺失时命主卡片写着「未知地（按标准时）」、风险条
明确说「出生地未落实…请先补出生地」，信息一点没丢，搜索框此刻恰好露出操作指引。

配套：

- ↑↓ 高亮、Home/End 首尾、Enter 选中、Esc 收起；Enter 一律 `preventDefault`，
  不再被表单当成提交（Home/End 是跟 tab 条的键盘习惯对齐，那边已经支持）
- **不高亮时按 Enter 什么都不做**，不替老师猜——「朝阳」有北京朝阳区和辽宁朝阳市，
  经度差 14 分钟，正好是能翻掉一个时辰的量级
- 补 `role="combobox"` / `aria-expanded` / `aria-controls` 与 `role="listbox"` /
  `role="option"` / `aria-activedescendant`，与本轮 ARIA 收尾保持一致
- CSS 只加了一条：`.city-opt-item.active` 复用已有的 `:hover` 配色，不新造视觉

三处调用点（录入表单、批量重名确认条、万年历页）共用这个组件，改一次全都受益。

## /simplify 顺带修掉的

- **候选列表改事件委托**：原来每敲一个字都给最多 10 条各绑一个 `mousedown`，
  打一个地名就是上百个闭包随即作废。现在 mount 时绑一次
- **`setActive` 只改变化的那两条**：原来每按一次方向键改写全部 10 条，
  20 次 DOM 写入里 16 次是空写；`scrollIntoView` 也改成只在真的看不见时才调
  （它每次都强制同步布局，这页有大张排盘表，代价比所有 DOM 写入加起来还高）
- **三个实例共用一棵城市树**：树只读、名录是同一个数组，原来各建一棵（每棵约
  3210 个包装对象、约 363KB）。更要命的是重名确认条随每次重排 `destroy` + 重新
  `mount`，等于每改一次日期就重建整棵树。按数组身份 memo 后全生命周期只建一次
- **监听器改 `AbortController`**：五对 add/remove 手工对账改成 `abort()` 一次
- 删掉 `results.removeAttribute('data-active')` 死代码（全仓从没设置过这个属性）
- `hideResults()` 开头短路：blur 的 150ms 定时器路径绝大多数时候下拉本来就是关的

## 验证

`npm test` 36/36。真实浏览器、真实按键：

| 用例 | 结果 |
|---|---|

| 点进去直接打字不拼接 | ✅ 框里就是「兰州」 |
| ↓ 高亮、再 ↓ 换条、↑ 回上一条 | ✅ `aria-activedescendant` 跟着走 |
| Home / End 跳首尾、首条再 ↑ 绕到末条 | ✅ |
| Enter 选中并回填下拉 | ✅ 面板收起、下拉填上、排盘出生地真的变了 |
| Esc 收起候选 | ✅ |
| 没高亮时 Enter 不乱猜 | ✅ 下拉纹丝不动 |
| 出生地缺失的命例 | ✅ 框空、下拉空；命主卡片与风险条各自明确告知 |

| JS 报错 | 无 |

像素回归（对照组 `1e59759`，同环境同一轮）：**六张全 0 差异**。
基线图停在「基本排盘」页，出生地控件在「快速录入」页，不在取景范围内。

过程中 `3-1024x768` 一度比出 11634 像素差异，查明是**首次对着新起的服务截图时
`.sheet` 底部投影带的冷启动伪影**，不是改动：四组交叉比对下，第一次对照截图跟其余
三组（对照第二次 + 改后两次）都差同一个 11634，而那三组互比全 0。判读规则已补进
`docs/baselines/2026-09-09-字号断点/README.md`——每组截两次，落单的那次丢掉。

## 没做

- **拼音搜索**（`lanzhou` → 兰州）：是新功能不是修 bug，要另外定口径（全拼？首字母？
  歧义怎么排），单开一轮
- **`lookupCity` 的缓存与 Collator 复用**（`engine/src/city.js`）：审查测出最坏查询
  「市」4.8ms，其中 `localeCompare` 占排序耗时 86%（每次比较隐式新建 Intl 排序器），
  且全命中排完序才取前 10。收益明确但动的是 `engine/`，本轮范围外
- **重名确认条每次重排都 destroy+mount**：树已经 memo 掉最大的一笔开销，
  但「picker 是长驻还是可抛」这个定性问题留着，单独排
- **REQ-002 酉用黄色**：继续搁置
