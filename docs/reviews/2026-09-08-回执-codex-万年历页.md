# 回执 · Codex · 万年历页（REQ-004 §4.2）

## 做了什么

- 新增独立「万年历」Tab，并在基本排盘工具栏和历法相关风险消息中增加入口。
- 复用时间、出生地通用控件；万年历持有独立状态，从盘页进入时复制当前盘，之后修改任一控件即隐藏对照结论，不回写排盘输入。
- 实现月页、本月节气、本日十二时辰、四柱自动对照、来源与精度声明五个区块。
- 月页显示农历、日干支、星期和带秒节气；所选日期朱砂高亮。
- 节气区显示节/气、交节前后、距出生时刻、节前后月柱，并显示 HKO 日期例外与 2057 年农历擦边提示。
- 时辰表显示北京时间区间、按出生地经度反推的北京时间区间、两派时柱与子时日柱差异；相同时合并展示。
- 对照区只指出逐柱一致或不一致；不判定哪一方正确，未出现竞品名称。
- 增加表外年份未交叉验证声明、构建白名单、老师试用说明和 README 文件表。
- 所有新增样式均使用 `alm-` 前缀，窄屏表格在自身容器横向滚动。

## 没做什么

- 未修改 `engine/`、通用控件、服务端、部署文件或其他非白名单文件。
- 未增加依赖、框架、校验规则、自动行为或硬编码业务上限。
- 未执行 `git add`、`git commit`。

## 引擎需要补什么

本次实现所需接口均已具备，未发现需要引擎补充或绕过的问题。

## 契约反馈

- 页面直接消费现有 `computeChart`、`calendar.js` 与 `solartime.js` 接口，无需修改冻结契约。
- 按任务书，万年历页计算展示用真太阳时；从盘进入的对照结论使用当前激活盘已经生效的北京时间、真太阳时与子时流派，避免重算口径漂移。
- 任务书同时规定时间控件范围为 1900–2100，并要求验证 1899 年提示。页面遵守控件范围；表外年份声明逻辑已实现并通过 `isYearVerified(1899) === false` 的可执行断言。若需老师直接从下拉选 1899，应另行确认是否放宽通用控件范围。

### 指定用例核对

- `2026-09-07 23:30` 兰州：白露为 `22:41:16`；输入时刻映射子时；子初换日日柱乙酉、早晚子时日柱甲申；当前盘与万年历推法四柱逐柱一致。
- 日期改动：控件回调会先将 `fromChart` 置为 `false`，再渲染，因此对照结论隐藏。
- `1979-01-20`：冻结表例外为大寒 `1979-01-21`，页面显示“老历书可能记在 21 日”。
- `1899`：`isYearVerified(1899)` 为 `false`，页面显示“本年节气时刻未经交叉验证”。
- 出生地：城市树和搜索均验证“北京市 → 朝阳区”“湖北省 → 仙桃市”可达。
- 375px：CSS 静态核对为页面容器不扩宽，月页和时辰表由 `.alm-table-scroll { overflow-x: auto; }` 自身横向滚动。
