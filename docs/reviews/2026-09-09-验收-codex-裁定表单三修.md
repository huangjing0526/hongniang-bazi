# 实机验收 · Codex 裁定表单三修

回执（`2026-09-09-回执-codex-裁定表单三修.md`）唯一没闭环的就是浏览器手工验收——
当时那个会话没有可连的浏览器。本次补跑，结论：**任务书清单全过，未发现新问题。**

## 怎么跑的

Claude 的 Chrome 扩展这台机器上连不上（Codex 当时卡的应该也是这个），改用
Playwright 驱动本机已装的 Chrome（`channel: 'chrome'`，没额外下载浏览器内核）。

- 被测对象：`cloud/server.mjs` 起的完整应用（含 API），不是 `web/server.js` 那个纯静态服务
- 端口 8099，`DB_PATH` 指向临时库，**没有碰 `data/hongniang-bazi.sqlite`**
- 每组用例前清库重启，浏览器每次新开 context，localStorage 从零开始
- 脚本在 scratchpad，不进仓库

## 任务二：防连点

| 用例 | 结果 | 实测 |
|---|---|---|
| 同一帧内连点两次「提交老师裁定」 | ✅ | 裁定数 0→1；**服务端 `/api/pull` 也只有 1 条** |
| 提交后不弹红色报错 | ✅ | `#verdict-error` 始终不可见 |
| 按钮忙碌态 | ✅ | 连点瞬间 `disabled=true`、文案「✓ 已提交」，之后复原为「提交老师裁定」且可用 |
| 硬刷新后立刻连点「解析并追加」 | ✅ | 只弹一条「已追加 2 条命例」，列表只追加一遍（6→8） |

用的是 `btn.click(); btn.click()` 同帧连发，比真人双击更极端。

## 任务三：神煞键盘可达与浮层焦点

真实按键（`page.keyboard.press`）跑的，不是合成事件——第一版我用 `dispatchEvent`
造 Tab，那种事件不会真的移动焦点，等于白过，已重跑。

| 用例 | 结果 | 实测 |
|---|---|---|
| chip 是原生 button | ✅ | 18 个全是 `<button>`，5 个带 `*`，无 `tabindex="-1"` |
| Tab 能走到 chip | ✅ | 从「对照万年历 →」按一下 Tab 即落到第一个神煞 |
| Enter / Space 打开口诀浮层 | ✅ | 两个键都能开 |
| 浮层语义 | ✅ | `role="dialog"` + `aria-modal="true"` |
| 打开后焦点进浮层 | ✅ | 落在关闭按钮上 |
| Tab 循环不外泄 | ✅ | 连按 10 次 Tab、6 次 Shift+Tab，焦点一次都没跑出卡片 |
| Escape 关闭并还焦点 | ✅ | 关闭后回到「福星贵人」那个 chip |
| 375px 布局 | ✅ | 页面横向溢出 0px，chip 全部在视口内，18 个 chip 高度统一 20px（换成 button 没撑开行距） |

全过程 console 无 error、无 pageerror。
