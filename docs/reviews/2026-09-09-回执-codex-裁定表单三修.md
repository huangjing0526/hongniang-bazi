# 回执 · Codex · 裁定表单三修

## 做了什么

### 1. 按命例保留裁定草稿

- 在 `renderVerdictForm()` 这个统一渲染入口判断命例 id 是否变化，避免在各种换盘路径分别挂钩。
- 换盘时先把当前 DOM 中的非空答案存到原命例草稿，再清空表单；目标命例有草稿时原样回填并提示。
- 草稿覆盖一致判定、分歧柱与干支、时间来源、流派与自定流派、理由、神煞异议与备注。
- 同一命例内切 tab、切历法开关、切夏令时双盘时 id 不变，不会触发存取。
- 提交成功后删除该命例草稿；删除命例、清空列表时同步删除相关草稿并清空当前表单。

### 2. 防止提交类动作连点

- 新增通用 `withBusy()` 包装，执行期间禁用按钮、替换忙碌文案，并在 `finally` 中恢复原文案与原 disabled 状态。
- 「提交老师裁定」「解析并追加到列表」「载入样盘库」均使用同一包装。
- `submitVerdict()` 另有模块级重入锁，防止通过 `window.app` 或其他非点击路径重入。
- 裁定提交成功后，按钮显示「✓ 已提交」约 1 秒后恢复。

### 3. 神煞键盘可达与浮层焦点管理

- 可点神煞由裸 `span` 改为原生 `button.shensha-chip`，自带 Tab / Enter / Space 操作。空值 `span.shensha-empty` 保持不变。
- CSS 沿用现有颜色、间距和圆角，重置按钮默认样式，并增加朱砂色 `focus-visible` 轮廓。
- 神煞卡片增加 `role="dialog"`、`aria-modal="true"` 和 `tabindex="-1"`。
- 打开时记住触发 chip 并把焦点移到关闭按钮；支持 Escape 关闭、Tab / Shift+Tab 在浮层内循环；关闭后把焦点还给原 chip。

## 草稿持久化选择

本次选择不持久化到 `localStorage`，只在当前页面会话中按命例保留。理由是这批数据尚未提交，不让过期半成品在刷新后自动回填，也不引入额外的存储版本、异常数据兼容与清理契约。任务要求的命例间来回切换会保留，页面刷新后草稿不保留。
