## 攻击面

### 1. 新旧章节打架

逐项核对新增的 §11–13 与已冻结的内容是否冲突，冲突就是重大或致命：

- §6「已冻结的产品口径」表
- §7.1 档位表 / §7.2 B 档页面清单 / §7.3 神煞冻结表
- §8 UI 朱砂卷宗
- §9 实现路径与验收
- §3.2 命理政策层（原来的两层拆法）与 §11 的五层拆法，是不是同一件事说了两遍、且口径不一致
- §2 结论表新加的「定位」「硬赢点」两行，和表里原有行有没有矛盾

### 2. 「可归因」定位能不能落到 UI ← 我认为这是最可能落空的一条

§11.1 把产品职能定义成「任何一次分歧，30 秒内定位到哪一层，并给出可切换的开关」。

- 对着 `prototype/index.html` 现在的实现说话：现有的「口径抽屉」和「对照页」离这个目标差多少？缺哪些组件？
- 五层归因（L1 天文 / L2 输入 / L3 口径 / L4 神煞表 / L5 老师私家表）要在界面上呈现，需要多大的信息密度？和 §8「密度高、手机优先」冲不冲突？
- **L2（输入错）和 L5（老师私家表）这两层，界面根本没法自动判定**——要判 L2 得知道时间来源可靠不可靠，要判 L5 得知道老师用的是哪张表。那「30 秒定位到层」是不是只能做到 L1/L3/L4？如果是，§11.1 那句话就要改

### 3. 五层归因是给谁看的

- 红娘老师关心的是「到底哪个对」，还是「分歧属于第几层」？
- 一个不懂天文历法的老师，看到「本盘分歧属于 L3 口径层，无唯一答案」会是什么反应——被说服，还是觉得我们在推卸责任？
- §11.3 红线写「分歧时不判老师错，UI 给『分歧点在 X』不给『正确答案是 Y』」。这条对老师是尊重还是**耍滑头**？老师花钱买的会不会恰恰就是「Y」？

### 4. §13.1 分歧风险扫描的呈现风险

文档说批量扫老师客户库，标出四类风险盘，「只标风险不给结论」，并称「这张表本身就是给老师的第一个价值证明」。

- 老师拿到「你手上 20 个盘有 6 个有分歧风险」，第一反应是「这工具有用」还是「你在吓我 / 你在说我以前的活都白干了」？
- 如果是后者，这个「第一个价值证明」就变成了第一次信任损失。有没有更安全的呈现方式？
- 这条如果站不住，§13 的整个先行动作顺序要重排

### 5. §11.1 三件护城河，哪几件是真的

文档列了三件问真做不到的事：①老师/机构口径与神煞表固化成配置 ②机构级一致性，多位老师出的盘口径统一 ③合婚与客户档案。

- 逐条判断：哪件是真需求，哪件是我们自己想出来的
- ②「机构级一致性」——红娘机构真的会要求多位老师口径统一吗？还是各老师本来就各有各的流派，统一反而是反需求？
- ③「合婚与客户档案」——这是 §7.1 明确划给二期/C 档的。把它写成护城河，是不是等于承认 B 档 MVP 本身没有护城河？如果是，那 §7.1 的档位划分要重排

### 6. 崩溃推演

假设 Grok 那边核实出「问真其实已经支持夏令时和真太阳时」：

- §12.1「唯一能硬赢的点」直接作废
- 此时 §11、§13 还剩什么？整个项目还成立吗？
- 请写出这种情况下的最小可行退路（或者明说「没有退路，应该停」）
