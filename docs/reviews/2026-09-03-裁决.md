## 一、三方收敛：§12.1「唯一能硬赢的点」必须降级

三方从三个互不重叠的方向打到同一个结论，这是本次审查最强的信号。

| 来源 | 打法 | 结论 |
|---|---|---|
| Grok C1/C2 | 查市场 | 2026 年已有 5+ 产品做齐「DST + 真太阳时 + 开关」：参天 AI、AstroBazi、FateMaster、辰时八字、mingli-fengshui。**是补课不是差异化** |
| Codex C-1 | 查数学 | 20.6% 是两个均匀假设相乘的模型值，不是人口事实。放开日内分布后严格区间 0–41% |
| Antigravity A-2 | 查产品 | 就算 DST 全对，B 档交付物仍是「问真单盘克隆」，零防守 |

**裁决**：§12.1 从「唯一能硬赢的点」降级为「必须做对的入场券之一」。

注意这不是否定 §11——恰恰相反，三方等于从外部确认了 §11.1 的判断（护城河不在引擎）。真正矛盾的是我在 §12.1 又把赌注押回了引擎。

**保留**：DST 仍是 L1、有唯一答案、值得做对，且仍可作为单个错例的演示。
**删除**：「唯一能硬赢」「每五个客户约有一个」这类话术。

## 三、机制型缺陷（单方致命，我接受）

### D1 · 三源对账不成立（Codex C-2）

我设计的三个「独立」实现，实际同源：

- tyme4ts 与 lunar-javascript 同属 6tail，一个作者
- tyme4ts 节气引自寿星
- sxtwl_cpp 是寿星的 C++ 移植

三票一致只证明共享同一上游，不证明对。且默认口径本就不同（lunar `sect=2`、tyme 偏 `sect=1`），归一化之后验的是配置层不是天文层。

判定表那句「三源一致 + 问真不同 → L1，问真错」是逻辑越级：差异仍可能来自输入标准化或三库共享的上游缺陷。

**改法**：机制降级为「差分回归」，不叫独立裁判。比对拆到天文原语层（节气绝对时刻 / 儒略日 / 连续纪日 / 四柱）。要真正的 L1 证据，须指定一个可追溯的权威历表当基准，而不是三票多数。

### D2 · 「30 秒定位到层」只能兑现 3/5 层（Antigravity A-1）

L2（输入错）在数据层面完全合法——农历误选公历、地点没改默认值，软件看不出来。L5（老师私家表）只能得出「与已知库全不符」，再往下判就是无根据指控，反而踩了 §11.3 自己的红线。

**改法**：改成有限承诺——L1/L3/L4 自动定位并给开关；L2 只给边界与闰月启发式预警；L5 只留自定义标注，不承诺归因。

### D3 · 夏令时 fold 二义性是数据模型缺陷，不是回归用例（Codex M-1 + Grok A5 双方确认）

结束日 01:00–01:59 走两遍，同一输入字符串对应两个瞬间（标准时 00:30 或 01:30，时支可能子可能丑）。「日期+钟表时+出生地」不足以唯一表示。

**改法**：数据模型加 `timeFold: first | second | unknown`；unknown 时输出双盘。§7.2「精确到分钟」这句要补注。

## 四、冲突项与裁决

### X1 · 20.6% 判「致命」还是「次要」

- Codex C-1：致命，是模型值不是人口事实
- Grok A3：次要，「量级还在，不必重写故事」

**裁决：不矛盾，合并处理。** Codex 攻的是认识论（不能当人口事实卖），Grok 攻的是数值（改 1988 后 20.5%）。两者都采纳：数字改 20.5%，标注为「全天全年均匀基准模型值」，删掉销售话术。Grok 说得对的是——量级足以支撑「值得做」，不足以支撑「唯一硬赢」。

### X2 · 「机构级一致性」是不是伪需求

- Antigravity A-5：重大，命理老师各承师门，强行统一口径是冒犯，机构真正要的是**品牌交付一致性**（统一卷宗视觉）不是算法一致性
- Grok C3：未验证。婚介 SaaS（婚恋云管家、赛信、163K、金媒）都是 CRM/配对，不是命理引擎；机构版命理市场无竞品可引用

**裁决：两方都没有证据，不由 AI 定案。** 我的原断言和 Antigravity 的反断言同为臆测。这条从「护城河」降为「待验证假设」，写进 §13.2 访谈问题清单，由老师回答。Antigravity 的替代提法（品牌交付一致性）作为候选并列，不预设哪个对。

### X3 · 归因面板要不要给倾向性建议

Antigravity A-7 建议在归因浮层加「行业惯例与验盘提示」，例如推荐向客户核对作息特征。

**裁决：驳回该改法，接受该批评。** 它提的做法实质就是给「正确答案是 Y」，直接违反 §11.3 红线。但它指出审计条是一串天文物理日志、没降低老师决策成本，这个批评成立。

**替代改法**：给**双盘并列 + 反推特征差异**（「按巳时断偏比肩，按午时断偏伤官」），把判断材料交给老师，我们不给倾向。

## 五、已实机验证（2026-09-03 补，见 [实机验证记录](2026-09-03-实机验证-问真Web版.md)）

Grok 的 B1/B2/B3 三条「未验证」当天在 Web 版 pcbz.iwzwh.com 结算：

| 断言 | 结果 |
|---|---|
| B1 问真不做夏令时回拨 | **部分成立，理由完全不同**：有开关，但勾选后四柱与真太阳时逐字段不变 |
| B2 问真不做真太阳时 | **推翻**。默认**开**，且经度差与均时差都做（三组命例手算误差 ≤1 分钟） |
| B3 默认流派 1 子初换日 | **成立**。早晚子时默认不勾 |

关键对照：兰州 1988-07-15 11:00，夏令时关 → `xls=0`、真太阳时 09:49、时柱癸巳；夏令时开 → `xls=1`、其余逐字段相同。若回拨生效，应为 08:49、时柱壬辰。跨 1986/1988 两年、两个地点、三个时刻结果一致。

**这对 §12.1 的降级判断是加强而非推翻。** 我们能赢的不是「问真没有这个能力」，而是「问真这个开关在 Web 版失效」——竞品修一版就没了，是最脆弱的一种优势。

同时它给了 §13.2 一个具体的错例来源：勾了夏令时以为已处理的老师，其 1986–1991 年出生客户的时柱整柱偏一位。

**对外话术红线**：只能说「同一命例两个工具结果不同，分歧点在夏令时」，不能说「问真算错了」——只测了 Web 版，App 与 VIP 未验证。元亨利贞/化几/爱五行/隔壁老王/寿星同样未逐个实机验证，不能把「未验证」说成「他们都不会」。

**新增待办**：补测子时交界（23:00–01:00）与早晚子时开关的实际效果、交节当天的年月柱行为。

顺带一条 Grok 的观察值得记：公开网络上**找不到**关于问真的可统计投诉簇（夏令时/真太阳时/子时/神煞都没有形成话题）。从业者评测多在夸界面和古籍参考。老师说「问真不准」在公网对不上具体技术点——这反而支持 §11 的判断：先采集错例，再定产品重心。

## 六、需要人拍板的一个决定

Antigravity A-2 指出的矛盾是真的，且我无法自行消解：

> §11.1 说护城河是「合婚与客户档案」，§7.1 却把合盘冻结在二期 C 档。
> 于是 B 档 10–12 天的交付物 = 去掉大运流年、20 个硬编码神煞、加了开关的问真单盘克隆。
> 而 §7.1「老师认四柱后再做合婚」是死锁：老师用着免费且更全的问真，没有动力去认一个功能更少的 Web 原型。

叠加 Codex M-2（工期在新增范围后应为 17–25 日，不是 10–12 日），必须二选一：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A · 保护城河** | 拆 C 档，砍单人细盘的十神副星长生细节，把「双人日柱合冲 + 纳音合 + 客户档案卡」并进 MVP | 第一版细盘不如问真，老师肌肉记忆受挫；工期重估 |
| **B · 保工期** | 坚守单盘 B 档，但 §11.1 删掉「合婚与客户档案是护城河」，明示 B 档只是算法验证桩、无商业壁垒 | 承认第一版没有留客理由，试用转化风险 |

Antigravity 的崩溃推演另给了一条更激进的退路 A′：允许老师继续用问真排盘，我方提供「问真干支一键导入」，把全部开发押在合婚图谱 + 可打印的朱砂卷宗交付物上。卖点变成「问真负责算盘，我们负责把盘变成能收费的卷宗」。
