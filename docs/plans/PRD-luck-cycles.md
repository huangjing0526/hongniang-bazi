# PRD · 大运流年（REQ-005）

> 对应 `docs/需求记录.xlsx` REQ-005，2026-09-10 Jing 决定放一期、独立做。
> 引擎已按 §4 实现并有 3 条回归（`engine/src/luck.js`、`engine/test/luck.test.js`），
> 与易百查截图样盘逐项对上。本 PRD 定的是**给老师看什么、怎么裁定**；页面样式走原型（Antigravity）。

## 1. TL;DR

老师看盘必看大运：几岁起运、走什么运、哪一年是什么流年。现在工具只排四柱，老师得另开一个 App 看大运，两边对着抄。本需求把大运流年排进工具：起运时长与交运时刻、十步大运、每步十个流年、起运前的小运，逐项可核；起运折算对齐问真样本（一小时折五天，显示到时），整时辰古法做成开关；裁定表单可以勾「起运或大运与我不一致」。只排、不判：不算老师《地支运算体系》里的岁运权重，不断引动，不断吉凶。

## 2. 背景与目标

### 2.1 背景

- 试用说明现在明写「不做大运流年」。老师核完四柱，第一反应是「大运呢」，没有它盘是残的。
- 排大运是纯历法：顺逆、起运、大运干支、流年干支，各家算法一致；**唯一分歧点是起运时长的折算**——按整时辰（3 天 1 年、1 时辰 10 天，尾数丢弃）还是按分钟（1 分钟折 2 小时）。易百查按分钟（截图给到「10 小时」），问真未核。
- 老师文档第五章（大运 ×0.6、流年 ×1.0、太岁特权）需要大运流年做输入。本需求只补输入，不做第五章。

### 2.2 目标与度量

| 目标 | 度量 | 目标值 |
|---|---|---|
| 老师不再另开 App 看大运 | 试用反馈 | 首批老师 ≥ 2 位说「够用」 |
| 起运口径可核 | 老师对起运岁数 / 交运日期的异议 | 每条异议都能归到「口径不同」或「出生分钟不详」，没有归不了因的 |
| 大运干支零错 | 老师对大运 / 流年干支的异议 | 0 条（这是纯算法，错了就是 bug） |

## 3. 用户故事

- **US-1 看大运**：作为老师，排完盘我在盘下看到「阴男逆行，2 岁 6 个月 23 天起运，2002-05-10 交运」，下面十步大运横排：年份、虚岁、干支、十神。
- **US-2 展开流年**：作为老师，我点某一步大运，展开它的十个流年，每年有干支与十神，我核客户「哪一年出的事」。
- **US-3 切起运口径**：作为按整时辰起运的老师，我在工具栏切到「整时辰」，起运时长变成「2 年 6 个月 20 天」，交运日期跟着变，大运干支不变。
- **US-4 裁定大运分歧（异常路径）**：作为老师，我认为起运应是 3 岁而不是 2 岁半，我在裁定表单勾「起运不一致」，填我认为的交运年份或岁数，选依据流派。工具记录当时的起运口径，事后能分清是口径不同还是算错。
- **US-5 出生分钟不详**：作为老师，客户只报「下午六点左右」，工具在起运行提醒「按分钟折算，出生时刻每差 1 分钟起运差 2 小时；分钟不详请以整时辰口径为准」。

## 4. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| F-1 | 起运信息行 | 顺 / 逆、起运时长「X 年 X 月 X 天 X 时」（默认口径显示到时；整时辰口径到天）、交运时刻（北京时，同上精度）、当前口径名。录入到分钟，小时数恒为偶数，与到秒的软件最多差 2 小时（决策记录 J-1） |
| F-2 | 十步大运表 | 每步：起止年份、起止虚岁、干支、十神（对日干）、藏干与副星、星运。第 0 项「起运前」不给干支，给小运 |
| F-3 | 流年展开 | 点一步大运展开其十个流年：年份、虚岁、干支、十神、藏干与副星、星运。默认收起，一次只展开一步 |
| F-4 | 小运 | 起运前逐年小运干支，**固定显示**，随第 0 项列出；从时柱起，男顺女逆（D-12）；界面注「小运起法各家不同，本表从时柱起男顺女逆」 |
| F-5 | 起运口径开关 | 工具栏加「起运：按分钟（显示到时）/ 整时辰」，默认按分钟（D-12）。**是本盘口径**，进裁定的口径快照（与子时流派同级，不同于自刑开关）；持久化为老师偏好 |
| F-6 | 裁定表单扩展 | 分歧柱多选之外加「起运不一致」「大运干支不一致」两项；勾了要填：认定的交运年份或起运虚岁 / 认定的大运干支；依据流派沿用现有下拉 |
| F-7 | 出生精度提醒 | 出生时间来源为「家人口述 / 客户自报」且口径为按分钟时，起运行显示 US-5 的提醒；来源为出生证不显示 |
| F-8 | 当前所在大运与流年高亮 | 按今天的日期标出正在走的那一步大运和当年流年，只是定位，不是判断 |
| F-9 | 夏令时重复小时 | 按 D-9：录入追问调回前后，答不上按调回前，起运行标注另一种时柱不改起运（起运只看北京时）。**双盘作废**，待落地 |
| F-10 | 响应式 | 十步大运在 375px 横向可滚（表格例外允许横滚），1024px 双栏下不挤右栏 |
| F-11 | 司令 | 起运信息行旁显示「司令：辛」，点开看分野表与本盘节后天数；整表标「待老师确认」（D-12、J-3） |
| F-12 | 流年提示 | 每个流年下一行文字：流年柱与原局四柱的整柱关系，按柱名列出，如「日柱天合地合、月柱天克地冲」，无则「无」（决策表 J-2，与问真样本一致）。不做色点。岁运天干 / 地支两支关系三行见 PRD-branch-relations F-20 |
| F-13 | 时辰未知 | 起运信息与大运区整体换成一句「时辰未知，无法起运」，流年行照常（D-6，待落地） |

## 5. 非功能与非目标

**非功能**

- 大运流年随排盘同步算出，实测约 1.7 毫秒 / 盘。
- 文案不出现「吉」「凶」「好运」「坏运」。

**非目标**

1. **不做流月、流日**。老师文档第五章 T30 流月等岁运层一起做。
2. **不做岁运引动判定**：太岁特权、反吟应期、封印解除、老师文档第五章权重，属 C 岁运层。**岁运关系的标注**（流年柱、大运柱对原局四干、四支、四柱的合冲等，只标有无）不在此列，见 PRD-branch-relations F-20 与决策表 J-13。
3. **不算老师的岁运权重**（×0.6 / ×1.0 / ×0.3）。
4. **不做「岁运并临」「运限年龄」「一柱论命」**等易百查、小南斗的附加行。年龄段各家不同，PRD-branch-relations §5 已排除。
5. **不做大运十神的吉凶解读**。
6. **不做农历起运**（按农历月日折算的旧法）：本期只做按节气的通行算法。

## 6. 业务规则

| 编号 | 规则 | 来源 | 状态 |
|---|---|---|---|
| BR-1 | 起运用「出生时刻」与「前后节的交节时刻」都按标准北京时；真太阳时只改日时柱，不改起运 | 与年柱、月柱交节口径一致（`chart.js` 冻结） | 已定；老师若按真太阳时起运另开开关 |
| BR-2 | 阳年男、阴年女顺行；阴年男、阳年女逆行。顺行数到下一节，逆行数到上一节 | 通行 | 已定 |
| BR-3 | 大运干支从月柱起，顺行往后、逆行往前，十步 | 通行 | 已定 |
| BR-4 | 流年干支按立春换年，与本工具年柱口径一致 | 通行 | 已定 |
| BR-5 | 岁数用虚岁：出生当年 1 岁 | 通行 | 已定 |
| BR-6 | 起运折算两口径：按分钟（3 天 = 1 年、1 小时 = 5 天，显示到时）/ 整时辰（3 天 1 年、1 天 4 个月、1 时辰 10 天，尾数丢弃）。**默认按分钟**，对齐问真样本 | 一期决策 D-12 | 已定；不再问老师 |
| BR-7 | 起运口径进裁定的口径快照 | 它改交运日期，老师说「起运不对」时必须知道当时按哪套算 | 已定 |
| BR-8 | 小运从时柱起，男顺女逆，固定显示，注「表不同」。历法库自带的是阳男阴女顺，不用它，引擎自推 | 一期决策 D-12 | 已定 |
| BR-9 | 司令按《三命通会》人元司令分野，节后天数按北京时交节起算，申宫首七日取戊 | D-12、J-3 | 冻结，待老师确认 |

## 7. 技术约束

### 7.1 数据一致性
- 裁定新增的两项分歧与现有裁定同一条记录、同一个 `id`，同步去重逻辑不变。
- 起运口径写进 `options` 快照，与 `sect` 同级；旧裁定的 `options` 没有这个键，分析时按「口径未知」处理，与 0002 迁移前的旧数据同一做法。

### 7.2 性能要求
排大运 ≤ 5 毫秒 / 盘（实测 1.7）；对照页 7 张盘合计 < 15 毫秒。

### 7.3 可观测性
N/A —— 浏览器内计算。老师异议走裁定回传，后台按新字段筛。

### 7.4 成本约束
N/A —— ¥0。

### 7.5 安全与合规
不新增 PII。裁定新增字段只含干支与年份。

### 7.6 第三方依赖
- `lunar-javascript` 的 `getYun` 系列。无独立第二实现；交节时刻已有冻结表交叉验证（REQ-004），起运依赖的前后节时刻若与冻结表相差 > 1 分钟，现有 `CALENDAR_MISMATCH` 风险会亮，本期不另做。
- 无网络调用，无超时与重试问题。

### 7.7 配置与开关
- 「起运口径」老师可见，默认按分钟（显示到时），存为偏好且进本盘快照。
- 回滚：前端不渲染大运区；引擎输出保留，契约里 `luck` 永远有值。

### 7.8 数据保留
随现有裁定表，无新增保留策略。

### 7.9 与现有契约的关系
- `Chart` 新增 `luck`（已实现，见 `contract.js` 的 `Luck` typedef）。
- `computeChart` 输入新增 `luckSect`（1 整时辰 / 2 按分钟，默认 2）。
- `Chart` 新增 `siLing`（已实现，`siling.js`）。
- 裁定扩展只做在试用版（J-6）；一期不带裁定表单（D-10）。
- `ChartOptions` 新增 `luckSect`（**契约变更**，须知会 web 与数据两方）。
- `Verdict` 新增 `disputedLuck`：`{ startAt?: string, daYun?: string }`，勾了对应项才有值（**契约变更 + 一条迁移** `0005`，`verdicts` 表加两列）。
- 裁定表单的「与我们一致」语义扩展为「四柱与大运都一致」。

## 8. 风险

| 编号 | 风险 | 类型 | 应对 |
|---|---|---|---|
| R-1 | 老师的起运口径不在两套之内（如按农历、按真太阳时、按「足日」但不舍时辰） | 业务 | 裁定表单的流派下拉可自填；收到第 2 条同类异议就加口径 |
| R-2 | 老师拿易百查等按分钟的软件对照，交运日期差几天，以为算错 | 业务 | F-1 起运行注明口径并可切；差异最多十天，大运干支不受影响 |
| R-3 | 老师看到大运后追问「这步运好不好」「岁运冲原局怎么判」 | 业务 | 区底声明「只排不判」；追问记入需求记录，归 C 岁运层 |
| R-4 | 十步大运 + 流年展开把盘页拉得很长，裁定表单被顶远 | 产品 | F-3 默认收起、一次一步；原型实测 1024 与 375 |
| R-5 | `Verdict` 契约变更与迁移在并发会话环境下撞车 | 工程 | 迁移文件走独立 worktree、定向提交（CLAUDE.md 约定） |
| R-6 | 试用说明写了「不做大运流年」，老师看到会问为什么改口 | 业务 | 更新试用说明：「大运流年已加，起运口径可切，仍不判」 |
