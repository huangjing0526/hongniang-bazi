# PRD · 地支关系标注

> 前置文档：`docs/2026-09-10-方案-地支运算体系产品化评估.md`（三层拆分与老师文档的三个问题）。
> v1.1（2026-09-10）：老师看了小南斗等几家的「灰线」后提出流通指示的想法，本版把「格上流通与合冲指示」从可选改为必做，新增天干五合、生克流通、宫位小字三项。参考截图在 `docs/资料/竞品流通指示-2026-09-10/`。
> 本 PRD 只覆盖 **A 标注层**。B 判定层、C 岁运层、大运流年各自另立 PRD，本文在 §5 非目标里画清边界。
> 交付顺序：本 PRD 定稿 → Antigravity 按本 PRD 出原型（`docs/2026-09-10-任务书-antigravity-地支关系原型.md`）→ 前端按原型实现。引擎侧已按 §4 实现并有 7 条回归（`engine/src/branch-relations.js`、`engine/test/relations.test.js`），原型不需要等它。

## 1. TL;DR

老师看盘的第一眼，除了四柱本身，就是四个地支之间「谁合谁、谁冲谁」。现在工具只排出四柱和神煞，这一层老师得自己在脑子里过。本需求把老师自己总结的《地支运算体系》里的关系表冻结进工具：排完盘，在细盘表格下方自动列出原局四支之间的合、冲、刑、害、破、三合、三会、半合、暗拱、伏吟、墓库、争合，每条标明落在哪几柱、隔多远、在老师的力量金字塔里排第几，点开能看老师的规则原文。同时在四柱格子上用细线把这些关系画出来：相邻干支之间谁生谁用箭头，合与冲用托底线加一个字标出，让老师一眼看到气在盘里怎么流。只说「有没有」，不说「灵不灵」、不断吉凶，老师的判断仍然是老师的。

## 2. 背景与目标

### 2.1 背景

- 老师 2026-09-10 交来《八字地支运算体系 V3.1》，把地支互动编成了代号表（K01–K12、D10–D12、W10–W13、T00–T30、G00–G02、V01–V02）。评估结论见前置文档：第一到九章可以直接产品化，第十章的生效判定规则有七处缺口，第十一章及下卷缺失。
- 现有产品定位是「排盘 + 老师裁定」，红线是「分歧时只指出分歧点，不给正确答案」。地支关系的「有无」是查表事实，各家基本一致，不触碰红线；「生效」「吉凶」才是流派分歧，本期不做。
- 老师文档页脚标注「部分内容可能由 AI 生成」，其中所有**数值**（藏干比例、宫位权重、距离百分比、岁运权重）需要老师逐组确认；本期只展示关系与距离档，数值一律不作为计算输入。

### 2.2 目标与度量

| 目标 | 度量 | 目标值 |
|---|---|---|
| 老师核盘时不再手工推关系 | 试用老师反馈「关系区有用 / 没用」 | 首批试用老师中 ≥ 2 位明确说有用 |
| 关系表与老师口径一致 | 老师对关系条目提出的异议数 | 试用两周内 ≤ 3 条，且全部可归因到 §6 里标「待确认」的规则 |
| 不误导为断吉凶 | 老师是否问「这条关系是好是坏」 | 若出现，说明文案没讲清，需改文案而非加功能 |

## 3. 用户故事

- **US-1 核盘看关系**：作为试用老师，排完一个盘后，我在细盘下方直接看到「巳酉 生旺半合（月·日）」「子酉 六破（年·日，隔一位）」这样的清单，不用自己数。
- **US-2 看规则出处**：作为老师，我点某一条关系，能看到这条在《地支运算体系》里的代号、星级、落在哪两个宫位、距离档对应的两套百分比、规则原文，确认工具用的是我的口径。
- **US-3 关掉我不认的口径**：作为不认自刑的老师，我在工具栏把「自刑」关掉，关系区的自刑条目消失，伏吟条目照旧；这个选择下次打开还在。
- **US-4 我认为某条不对（异常路径）**：作为老师，我看到「寅丑 暗合」旁有 * 号，点开写着「口径待老师确认」；我想反馈，本期只能在裁定表单的「一句话理由」里写。工具不能假装没有分歧。
- **US-5 空态**：作为老师，我排到一个四支之间什么关系都没有的盘，关系区明确写「本盘四支之间无合冲刑害破，亦无墓库」，而不是留白让我怀疑没算。

## 4. 功能需求

| 编号 | 需求 | 说明 |
|---|---|---|
| F-1 | 关系清单 | 对原局四个地支输出以下关系：两支：六合、六冲、六害、六破、暗合、相刑（含子卯无礼之刑）、伏吟、自刑；三支：三会、三合、三刑、争合；两支派生：生旺半合、旺墓半合、暗拱；单支标签：墓库（丑金库 / 辰水库 / 未木库 / 戌火库） |
| F-2 | 每条条目的必备信息 | 涉及地支（按柱序）、关系名、合化结果 / 刑名 / 拱出之字 / 库名（有则显示）、落在哪几柱、距离档（两支：相邻 / 隔一位 / 隔两位；三支：三支相连 / 三支有隔）、老师文档代号与星级、是否「口径待老师确认」 |
| F-3 | 展示位置 | 细盘十行表格**之下**、神煞说明之后，作为同一张「卷宗」的延续。不改十行的行序（老师肌肉记忆），不插入为第十一行 |
| F-4 | 分组 | 按「三支格局 / 两支关系 / 墓库」三组展示，组内强者在前（老师金字塔：三会 ＞ 三合 ＞ 六合 ＞ 六冲 ＞ 三刑 ＞ 六害 ＞ 六破；伏吟、墓库垫底） |
| F-5 | 条目可点 | 点一条弹出详情：标题（地支 + 关系名）、代号与星级、位置（柱名 + 宫位名 + 地支）、结果、距离（两套百分比并列：断具体事件 / 断人生大局；隔两位附文档备注）、备注、规则原文。复用现有神煞弹层的交互与关闭方式 |
| F-6 | 冲突类与合作类视觉区分 | 冲、刑、害、破用朱砂系；合、会、拱用金系；墓库用中性色。原型定具体样式 |
| F-7 | 格上合冲指示（**必做**） | 在细盘的天干行与地支行上，用托底线加一个字把合与冲画出来：地支六合、六冲、三合、三会，天干五合（F-15）。不论隔几柱都画（BR-13）。害、破、刑、半合、暗拱、伏吟、争合**默认不画**，留在文字条目里（BR-16，待老师看过原型后定）。参考 `06-小南斗` 图里「卯 ⌐ 酉 冲」与 `01-小南斗` 图里「丁 ⌐ 壬 木」的画法 |
| F-8 | 自刑开关 | 工具栏增加「自刑」勾选，默认开（老师模型口径），关闭后自刑条目不出、伏吟不受影响；持久化为老师偏好；不改四柱，不进裁定的口径快照 |
| F-9 | 待确认标记 | 老师文档中非共识口径（暗合只取寅丑、午亥两对）在条目上标 *，弹层写明「口径待老师确认」，与神煞的 * 一致 |
| F-10 | 常驻声明 | 关系区底部一行：据老师《地支运算体系 V3.1》第一至九章冻结；隔位关系仍列出，折扣见弹层；自刑与暗合为本模型口径；合解冲、冲破合、化气、封印属生效判定，本期不做 |
| F-11 | 空态 | 无任何关系时显示明确的空态文案（见 US-5） |
| F-12 | 响应式 | 375px 单栏与 1024px 双栏都可用；条目换行不截断；1024px 双栏下关系区不能把右栏裁定表单顶出首屏（现有断点约定见 `docs/2026-09-09-任务书-antigravity-字号与断点.md`） |
| F-13 | 双盘 | 夏令时重复小时输出双盘时，两盘各自的关系区独立，切换盘时关系区跟着切 |
| F-14 | 生克流通线 | 在天干行与地支行之间、相邻两柱之间画细灰线：**生**用箭头，从生的一方指向被生的一方；**同五行**用无箭头平线；**克不画线**（F-16）。只画三处：同一柱的天干与地支之间（竖）、相邻两柱的天干之间（横）、相邻两柱的地支之间（横）。隔柱不画（BR-12）。参考 `01-小南斗`：庚→壬、壬↓寅、丑—戌 |
| F-15 | 天干五合托底线 | 甲己、乙庚、丙辛、丁壬、戊癸五对在天干行上画托底线，标所合五行（土 / 金 / 水 / 木 / 火）。只标「合」不判「化」（BR-15）。天干合的数据由引擎新增天干关系输出（§7.9） |
| F-16 | 克以文字列出 | 相邻干支之间的克不画线，在关系区文字条目之外加一行「天干本命：己克癸、癸克丁」式的短文。参考 `06-小南斗` 页底。范围同 F-14 的三处 |
| F-17 | 柱名下标宫位 | 细盘表头「年柱 / 月柱 / 日柱 / 时柱」下方加一行小字：祖上宫 / 月令 / 夫妻宫 / 子女宫（老师文档第二章，`PILLAR_PALACE`）。不加年龄段（§5 非目标 7） |

## 5. 非功能与非目标

**非功能**

- 关系计算随排盘同步完成，老师感知不到延迟（引擎实测约 7 微秒 / 盘）。
- 关系区文案全中文，不出现 K03 / D10 这类代号作为主文案；代号只在弹层作为「老师文档对照」出现。

**非目标（本期明确不做）**

1. **不判生效**：合解冲、冲破合、化气 / 合绊、封印、墓库开闭（G01 / G02）、争合裁决，属 B 判定层，等老师回答评估文档 §3 的七个缺口后另立 PRD。
2. **不做岁运**：大运、流年、流月的引动、太岁特权、反吟、真冲虚冲，属 C 岁运层，依赖大运流年功能（REQ-005 候选，未立项）。
3. **不用文档里的数值算分**：宫位权重 1.5 / 1.2 / 0.8 / 0.6、藏干 60 / 30 / 10、岁运 0.6 / 1.0 / 0.3 只在弹层作为「老师文档写法」展示距离两套百分比，不参与任何计算、不做汇总分。
4. **不改藏干顺序**：巳的中气 / 余气顺序（老师文档「丙戊庚」 vs 引擎与问真「丙庚戊」）等老师拍板，本期不动。
5. **不加裁定字段**：「地支关系异议」不进裁定表单与数据库；老师本期用「一句话理由」反馈。加字段需扩契约与迁移，单独排。
6. **不做天干判定**：丑戌未三刑的「天干重克则仅虚象」修正需要天干模块的强弱判断，本期只标三刑并在备注写明未判。F-15 的天干五合与 F-14 的干支生克是查表事实，不是判定，不在此列。
7. **不做年龄段**：小南斗按 0–15 / 16–30 / 31–45 / 46 后，易百查按 16 岁前 / 17–32 / 33–48 / 49 岁后，两家不同，属流派分歧，本期不进表头。
8. **不做五行百分比与格局喜用**：五行圆环要用藏干权重（老师待确认数值）；格局、喜用、幸运色是断命，红线不做。

## 6. 业务规则

| BR-16 | 格上默认只画六合、六冲、三合、三会、天干五合；害、破、刑、半合、暗拱、伏吟、争合不画 | 小南斗只画合冲；画多了图面乱 | 待老师看过原型后确认 |

## 7. 技术约束

### 7.1 数据一致性
N/A —— 关系是纯函数输出，不落库、不同步；同一四柱 + 同一自刑开关必得同一清单，回归测试保证（`engine/test/relations.test.js`）。

### 7.2 性能要求
关系计算 ≤ 1 毫秒 / 盘（实测约 7 微秒）；对照页每次渲染最多算 7 张盘，总增量 < 0.1 毫秒。

### 7.3 可观测性
N/A —— 浏览器内计算，无服务端事件。老师反馈走现有裁定回传，后台按 `verdicts.reason` 里含「关系」「合」「冲」「刑」等关键词人工筛。

### 7.4 成本约束
N/A —— 无外部调用，每日成本 ¥0。

### 7.5 安全与合规
不新增任何 PII；关系区只依赖四柱。

### 7.6 第三方依赖
无新增。关系表为项目自研数据，据老师文档整理，不取自任何 GPL 实现。

### 7.7 配置与开关
- 「自刑」为老师可见开关，默认开，存于本机偏好。
- 整个关系区无独立总开关；回滚方式是前端不渲染该区块（引擎输出保留，契约里 `relations` 字段永远是数组）。

### 7.8 数据保留
N/A —— 不产生新数据。

### 7.9 与现有契约的关系
- `Chart` 新增 `relations: Relation[]`；`Pillar`、`DETAIL_ROWS`、`Verdict`、`ChartOptions` 均不变。
- `computeChart` 输入新增 `selfPunish`（默认 true）。
- v1.1 新增两组输出，形状由引擎侧定、原型不依赖：
  - **干支生克流通**：F-14 三处位置各一条记录，含起点、终点、类型（生 / 同 / 克）；克只供 F-16 文字用。
  - **天干关系**：天干五合（含所合五行）；天干相冲（甲庚、乙辛、丙壬、丁癸）本期只出数据不画，等老师定。
- 引擎实现在原型定稿后做；地支五行表与天干五合表是十来行的常量。
