## 目标

老师能在一页上看到：这个月每天的日干支与农历、本月节气的准确交节时刻（带秒）、这一天十二时辰在他出生地对应的北京时间与时柱、以及本盘四柱与万年历推法逐柱是否一致。

## 页面结构

### 入口

1. 顶部 tab 栏加第五个 tab：`<div class="tab" id="tab-btn-almanac" onclick="window.app.switchTab('almanac')">万年历</div>`，对应 `<div id="tab-almanac" class="tab-pane">`。`switchTab('almanac')` 时调用 `renderAlmanac()`（照 `compare` 的做法：藏着时不算）。
2. 盘页工具栏（`.toolbar`，「朱批过程」按钮旁）加一个按钮「对照万年历 →」：带着当前盘跳过去（见下「从盘进来」）。
3. 风险条里 `JIE_QI_DAY` / `JIE_QI` / `CALENDAR_*` 四类消息末尾加一个「查看万年历 →」链接，同样跳过去。链接文字由 `renderRisks` 拼，点击走 `window.app.openAlmanacFromChart()`。

### 顶部：时间 + 出生地（复用控件）

```js
import { mount as mountDateTimePicker } from './components/datetime-picker.js';
import { mount as mountRegionPicker } from './components/region-picker.js';
```

- `DateTimePicker`：`mount(el, { value, onChange, minYear: 1900, maxYear: 2100 })`，值形状 `{year,month,day,hour,minute}`。
- `RegionPicker`：`mount(el, { value: cityName, cities, lookup, onChange })`，`onChange(entry)` 给 `{name,lng,lat,approx,level}`。城市库是懒加载的：挂载时 `state.cities` 可能还是空数组，照 `app.js` 里 `feedRegionPickers()` 的做法，把万年历页的实例也加进 `pickers`，城市库到了统一喂。
- 另加一个子时流派单选（子初换日 / 早晚子时），默认跟 `state.input.sect`。
- 页面自己持有一份 `almanacState = { year, month, day, hour, minute, cityName, longitude, sect }`，**不写回 `state.input`**——老师在万年历页随便翻日期，不能把正在核的盘改掉。

### 从盘进来（`openAlmanacFromChart()`）

把 `state.input` 的时间 / 出生地 / 经度 / 生效的 `sect` 拷进 `almanacState`，`fromChart = true`，切 tab、渲染。老师之后在万年历页改了任何控件，`fromChart` 置 false，「对照结论」区块隐藏（改了输入就不再是那张盘）。

### 区块一：月页

选中月份逐日一行，仿纸质万年历：

| 列 | 取法 |
|---|---|
| 公历日 | 循环 1..月末 |
| 星期 | `new Date(Date.UTC(y, m-1, d)).getUTCDay()` |
| 农历 | `Solar.fromYmd(y,m,d).getLunar()`：`getMonthInChinese()` + `getDayInChinese()`，初一那行写月名（含「闰」，`getMonth()<0` 为闰月），其余写日 |
| 日干支 | `dayGanZhiByJdn(y, m, d)`（`calendar.js`，**不走 lunar**） |
| 节气 | `jieQiTableOf(y)` 里 `at` 落在这天的，写「白露 22:41:16」（用 `fmtTerm(t).slice(11)`） |

`Solar` 从 `lunar-javascript` 来：`import { Solar } from 'lunar-javascript';`（`web/index.html` 已有 importmap，`app.js` 同款用法见 `engine/src/chart.js`）。

出生日整行朱砂高亮（类似 `.col-day` 的浅朱底 + 左朱线）。

### 区块二：本月节气

本月的两条（节 + 气）各一行：名称、`fmtTerm(t)`（带秒）、距出生时刻多少（`±X 小时 Y 分`，用 `t.seconds - toEpochSecond(beijingOfInput)`），出生时刻落在节前 / 节后用箭头标出。「节」那行加一句：这之前月柱是 X、之后是 Y（`monthGanZhiAt` 分别对交节前一秒与后一秒算）。

北京时怎么来：`computeChart({...almanacState 的时间与经度, applyDst: state.input.applyDst, applyTrueSolar: true, sect, cityKnown: true})` 取 `charts[0].times.beijing` 与 `.trueSolar`——夏令时回拨与真太阳时的逻辑都在引擎里，页面不要自己算。

### 区块三：本日时辰表

12 行（子…亥），列：

| 列 | 取法 |
|---|---|
| 时辰 | `ZHI[i]` + 「时」 |
| 北京时区间 | 子 23:00–01:00，丑 01:00–03:00 … |
| 本地真太阳时对应的北京时区间 | 真太阳时 = 北京时 + offset，offset 由 `trueSolarOffsetMinutes(beijing, longitude).totalMinutes`（`engine/src/solartime.js`）得到；**北京时 = 真太阳时 − offset**，区间两端各减一次。写成「00:05–02:05」并注明 offset 是多少分钟 |
| 时柱（子初换日） | `dayTimeGanZhiAt({...date, hour: 该时辰的代表小时}, 1).time` |
| 时柱（早晚子时） | 同上 `sect=2`；只有子时那行两派可能不同，其余行相同——相同就合并显示，别让老师看两列一样的字 |
| 日柱 | 子时行标出「23 时：子初换日按次日 X，早晚子时按本日 Y」 |

出生时刻所在的时辰那行高亮。

### 区块四：对照结论（只在 `fromChart` 时显示）

```js
const chart = getActiveChart();
const ours = almanacPillars({ beijing: chart.times.beijing, trueSolar: chart.times.trueSolar, sect: state.input.sect });
```

逐柱：`chart.pillars[k].ganZhi` vs `ours[k]`，四列，一致打「一致」，不一致把两个干支并排、标朱砂并写「此柱两种推法不一致，请以万年历页为准复核」。**不给结论、不说谁对。** 引擎测试已证明两者在 1500 个随机盘上逐柱一致，所以这一区块正常永远全绿——它存在的意义是出了问题不会静默，和风险条一个道理。

### 区块五：来源与精度声明（常驻页脚）

从 `engine/data/jieqi.SOURCE.md` 抄要点，老师能看懂的话：

- 节气时刻据本工具冻结表（北京时间，精确到秒）；表由独立天文算法生成，与香港天文台 1901–2100 逐年核对。
- 「各家万年历有的截断到分、有的四舍五入，所以这里带秒显示。」
- 表外年份（1900 前 / 2100 后）：显示「本年节气时刻未经交叉验证」（`isYearVerified(year)` 为 false 时）。
- **已知例外要在对应年份弹出来**：`HKO_DATE_EXCEPTIONS[year]` 有条目时，在区块二那条节气旁标「老历书可能记在 X 日」；2057 年 9 月加一句「2057-09-28 各家历书对是八月三十还是九月初一不一致」。
- GeoNames 署名已在页脚 `.attribution` 里，**不要删**（CC BY）。

## `calendar.js` 你要用到的接口

```js
import {
  TERM_NAMES, JIE_NAMES, TABLE_RANGE, HKO_DATE_EXCEPTIONS,
  jieQiTableOf,      // (year) → Term[24]，Term = { name, index, at:{year,month,day,hour,minute,second}, seconds, minutes, source:'table'|'lunar' }
  isYearVerified,    // (year) → boolean
  jieQiOfDay,        // (beijing) → Term | null
  nearestJie, jieBefore,
  fmtTerm,           // (Term) → '2026-09-07 22:41:16'
  toEpochSecond,
  dayGanZhiByJdn,    // (y, m, d) → '甲申'
  yearGanZhiAt, monthGanZhiAt,   // (beijing) → { ganZhi, ... }
  dayTimeGanZhiAt,   // (trueSolar, sect) → { day, time }
  almanacPillars,    // ({ beijing, trueSolar, sect }) → { year, month, day, time }
  hourZhiIndex,      // (hour) → 0..11
} from '../engine/src/calendar.js';
import { trueSolarOffsetMinutes } from '../engine/src/solartime.js';
import { GAN, ZHI } from '../engine/src/contract.js';
```
