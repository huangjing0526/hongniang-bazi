# 红娘八字排盘 · 调研与 MVP 方案

- 日期：2026-09-03
- 状态：口径与皮肤已定，引擎与正式页面未开工
- 决策人：产品（本仓库会话）+ 待红娘老师终验命例
- 原型：[`../prototype/index.html`](../prototype/index.html)

---

## 1. 背景与目标

红娘机构试用市面流行的「问真八字」，反馈 **部分排盘不准**，需要我们做可测试、可修正的 MVP。

> **2026-09-03 口径校准（来自机构本人，权重高于本文档任何推断）：**
> 对方的原话是 **「问真 98% 是对的，只有部分场景有错误」**，并同意 **先做 MVP 给他们做测试**。
>
> 这两句改变了项目性质：
> 1. 命题不是「问真不准」，是「问真在 2% 的边缘场景出错」。**没有人会为 2% 更换一个免费且成熟的工具**——所以「做一个更准的排盘器去替代问真」这条路直接排除。
> 2. 98% 一致意味着问真本身就是一个免费、现成的回归基准，可以用来钉死我们引擎的天文层。
> 3. 稀缺资源不是算法，是**老师愿意做测试**这件事。MVP 的成功标准应是「拿到并留住这个测试通道、把那 2% 的真实场景采集出来」，不是「打败问真」。
>
> 本文档 2026-09-03 之前写的「硬赢点」「更准」相关论述，均在此前提下作废，以 §11、§12.3 为准。

目标不是再做一个算命 App，而是给老师一张：

1. 细盘结构跟问真一样好扫
2. 历法计算可审计、口径可切换
3. 和问真不一致时，能分清是「历法/口径」还是「神煞表不同」

**不做：** AI 批命、合婚百分制、GPL 问真仿品商用、从零写节气算法。

## 3. 「准确」拆成两层

> 2026-09-03 补：实际投诉里还有输入错误、神煞表、老师私家表三类，两层不够用。完整五层归因见 [第 11 节](#11-分歧归因五层拆法2026-09-03-补)。

### 3.1 天文历法层（必须有唯一正确答案）

| 环节 | 正确做法 | 问真/市面常见翻车 |
|---|---|---|
| 年柱 | **立春交节时刻**换年，不是正月初一，也不是元旦 | 立春当天差一年 |
| 月柱 | 十二「节」交节时刻换月，不是农历初一 | 立秋当天上下午月柱不同 |
| 日柱 | 六十甲子连续纪日 | 子时是否换日 |
| 时柱 | 两小时一时辰；时干五鼠遁 | 交界 ±10 分钟 + 真太阳时会跳柱 |
| 农历 | 只用于展示/输入；闰月必须能区分 | 用农历年当干支年 |
| 夏令时 | 中国 1986–1991 出生证时间回拨 1 小时；逐年起止见 §12.1 | 有开关但不生效；或起止表抄错 4-10 |
| 真太阳时 | 钟表时 + 经度差 + 均时差（EoT，一年约 ±16 分钟） | 只做经度、或完全不做。**问真两项都做，且默认开**（§12.3） |

公式：

```
真太阳时 = 北京时间 + (当地经度 − 120°) × 4 分钟 + 均时差 − 夏令时
```

节气是否也换算成真太阳时，业内不统一。寿星万年历常用方案：**只校正日柱/时柱，年柱月柱仍用北京时间交节**。本项目按此冻结。

### 3.2 命理政策层（没有唯一答案，必须可切换、可审计）

| 政策 | 流派 1（子初换日，今主流、问真默认） | 流派 2（早晚子时） |
|---|---|---|
| 23:00–23:59 | 日柱算**次日**，时柱次日子时 | 日柱仍**当天**，时柱用次日子时 |
| 00:00–00:59 | 日柱次日 | 日柱次日 |

神煞、藏干余气、大运「三天折一年」的足日/实时，各家不同。这些不要宣传成「我们比问真更准」，要做成「口径写死 + 老师可改」。

### 3.3 素材与出处

- 历法：许剑伟《寿星天文历》；国标 GB/T 33661-2017《农历的编算和颁行》；Jean Meeus *Astronomical Algorithms*（均时差）
- 四柱口诀：《渊海子平》（五虎遁、五鼠遁、十神、十二长生）
- 神煞：《三命通会》（红鸾、天喜、桃花等）
- 格局/用神：二期再动《滴天髓》《穷通宝鉴》

**禁止用大模型直接「排八字」。** 四柱是确定性计算。

## 4. 黄金用例：Alanzhou · 1996-08-10 12:03

问真截图与 `tyme4ts` / `lunar-javascript` 对钟表时间的细盘 **逐字段一致**：

- 农历：1996年六月廿六 午时 · 坤造
- 四柱：丙子 丙申 己卯 庚午

| | 年柱 | 月柱 | 日柱 | 时柱 |
|---|---|---|---|---|
| 主星 | 正印 | 正印 | 元女 | 伤官 |
| 天干 | 丙 | 丙 | 己 | 庚 |
| 地支 | 子 | 申 | 卯 | 午 |
| 藏干 | 癸水 | 庚金 壬水 戊土 | 乙木 | 丁火 己土 |
| 副星 | 偏财 | 伤官 正财 劫财 | 七杀 | 偏印 比肩 |
| 星运 | 绝 | 沐浴 | 病 | 临官 |
| 自坐 | 胎 | 病 | 病 | 沐浴 |
| 空亡 | 申酉 | 辰巳 | 申酉 | 戌亥 |
| 纳音 | 涧下水 | 山下火 | 城头土 | 路旁土 |

问真字段约定（实现时不要混）：

- **星运** = 日干 vs 该柱地支（十二长生）
- **自坐** = 该柱天干 vs 该柱地支
- `lunar.getYearDiShi()` 一类 API 通常只给星运，自坐要另算

同盘若出生地按 **兰州 103.82°E** 做真太阳时：

| 出生地 | 修正 | 真太阳时 | 时柱 |
|---|---|---|---|
| 上海 121.5°E | +1 分 | 12:04 | 仍庚午 |
| 北京 116.4°E | −19 分 | 11:44 | 仍庚午 |
| 广州 113.3°E | −32 分 | 11:32 | 仍庚午 |
| **兰州 103.8°E** | **约 −70 分** | **约 10:54** | **己巳** |
| 乌鲁木齐 87.6°E | −134 分 | 09:49 | 己巳 |

己巳时柱（口径开真太阳时）校正：时干己相对日干己为 **比肩**（不是正官）；纳音大林木；空亡仍戌亥；星运/自坐帝旺。

立秋 1996-08-07：08:00 仍乙未月，14:00 已丙申月。子时 23:30：流派 1 日柱庚辰，流派 2 日柱己卯。

西部、时辰交界、立春/立秋前后，是「问真不准」高发区。本命例人名 Alanzhou，若确为兰州，问真按 12:03 排午时，老师用真太阳时会认定时柱错。

回归集至少覆盖：本盘、兰州变柱、立春/立秋交界、23:30 子时两派、1986–1991 夏令时。老师提供的「问真错例」进同一套 CI。

## 5. 开源项目怎么用

| 项目 | 协议 | 用法 |
|---|---|---|
| [tyme4ts](https://github.com/6tail/tyme4ts)（及 py/java） | MIT | **历法层首选**。6tail 称 lunar 只修 bug，新功能走 Tyme。节气引自寿星。默认子时偏流派 1。真太阳时要自加 |
| [lunar-javascript](https://github.com/6tail/lunar-javascript) | MIT | 细盘字段最全；截图盘可逐字段对上。默认 sect=2（早晚子时） |
| [cantian-ai/bazi-mcp](https://github.com/cantian-ai/bazi-mcp) | ISC | API 可参考。无真太阳时；默认 sect=2，和问真相反 |
| [@openfate/bazi-engine](https://github.com/openfate-ai/bazi-engine) | MIT | 政策开关较完整；底层仍是 lunar；要回归钉死 |
| shunshi-bazi-core | MIT | 自称默认 sect=1 对齐问真。对齐问真 ≠ 老师认为的准 |
| [sxtwl_cpp](https://github.com/yuangu/sxtwl_cpp) | BSD-3-Clause | 可商用（保留版权声明、禁止用其名背书）。寿星 C++ 移植，差分对照用，不是产品层。官方绑定为 SWIG Python/Lua/Java，无官方 JS/WASM |
| [8Char-Uni-App](https://github.com/axbug/8Char-Uni-App) | GPL-3.0 + README 禁止商用 | UI 几乎是问真。**商用不能用代码** |

推荐组合：

```
出生钟表时 + 出生地
  → 夏令时回拨（1986–1991）
  → 真太阳时（经度 + Meeus/NOAA 均时差）
  → tyme4ts 或 lunar-javascript 排四柱
  → 命理表：十神 / 藏干 / 纳音 / 空亡 / 十二长生 / 冻结神煞
  → 细盘 JSON + 逐步审计
```

### 5.1 GPL 仿品边界（已拍板）

仓库 LICENSE 为 GPL-3.0，README 另写「仅供学习研究、禁止商用」。条款打架时按更严的来。

| 做法 | 行不行 |
|---|---|
| 浏览器打开作者演示站，或自己电脑 clone 不给客户 | 可以 |
| 部署给红娘机构试用、换皮给老师测 | **不要** |
| 看过源码再「重写」进商用仓 | **高风险（衍生作品）** |

自研干净室：写产品的人只拿问真截图 + 本文件字段清单 + MIT 引擎。神煞/藏干表从古籍或 lunar/tyme 的 MIT 实现来，不从 GPL 仓抠。

### 5.2 地理数据的许可证陷阱（2026-09-03 补，差点踩）

真太阳时要出生地经度，于是要一份省市区坐标表。**这里有一个仓库许可证看不出来的坑：**

> 仓库挂 MIT / 木兰，不等于里面的坐标能商用。若坐标是从高德或百度接口抓来的，
> 受制于接口方条款，**不能存储、缓存、或据以生成数据库**——仓库作者无权把这个权利转授给你。

高德条款原文（lbs.amap.com/pages/terms/）：「您不得直接存储、缓存或技术手段抓取、使用本服务内部数据……亦不得……创造本服务及相关内容的衍生品（包括生成或用于数据库）。」

| 候选 | 覆盖 | 许可证 | 能否商用离线 |
|---|---|---|---|
| **GeoNames CN dump** | ADM3 约 2938（县级）、ADM4 约 11108 | **CC BY 4.0** | **可以**，须署名。**首选** |
| `mingyu-core`（npm） | 34 省 / 392 市 / 3210 区县，带经纬度 | MIT | 可能可以——**坐标出处未拆包核实**，用前必须查 |
| AreaCity（xiangyuecn） | 三级中心点 + 边界 | 仓库 MIT，**坐标来自高德** | **不可以** |
| `simonkuang/cn-pcas-geo` | 3209 区县 | **无 LICENSE 文件**，坐标来自高德 | 不可以 |
| `88240/city-geo` | 省31/市342/区县2995 | 木兰宽松 v2，**坐标来自百度 API** | 存疑，且数据停在 2020 |
| `china-division` / `province-city-china` | 区划全 | MIT | **没有经纬度**，只能配坐标用 |

**冻结决定**：`engine/data/cities.json` 走 **GeoNames CN dump（CC BY 4.0）**，产品内保留署名。禁止把高德/百度抓来的中心点进仓库，无论外层仓库挂什么许可证。

注意 GeoNames 的县级是地名录行政驻地，不是民政部最新区划码表，改名与撤县设区会滞后。**取经度够用，不能当行政区划主数据。**

## 7. MVP 范围

### 7.1 档位

| 档 | 内容 | 工期（1 全栈） | 状态 |
|---|---|---|---|
| A 对照原型 | 四柱 + 真太阳时/子时开关 + 审计 | 5–7 日 | 不单独做 |
| **B 试用 MVP** | A + 问真基本排盘字段 + 交界预警 + 老师备注 | **12–17 日** | **当前（2026-09-03 定：先让老师能上手测排盘）** |
| C 合盘 | B + 日柱合冲、十神互看、合婚神煞 | +4–5 日 | **降级为可选**。问真合盘已存在且是会员付费点，见 §12.3 |

**B 档的定位（重要，不要写成对外话术）：**

B 档是**拿到并留住老师测试通道的敲门砖，不是有壁垒的产品**。理由：

- 机构自述「问真 98% 是对的」（§1），没有人会为 2% 更换一个免费且成熟的工具
- 问真的排盘、合盘、案例库三件都有（§12.3），排盘域没有可赢的空间
- 老师必须看到完整的盘才判断得了我们准不准，所以**不能**只做「风险提示」，细盘字段要够他扫

因此 B 档的成功标准是：**老师愿意持续拿命例过来测**，以及**那 2% 的真实场景被采集出来**。不是「老师改用我们排盘」。

工期从 8–12 日改为 12–17 日：加入了夏令时表、`timeFold` 处理、审计 JSON 与回归；同时砍掉了三源差分 CI（改用问真本身当对照基准）、五层归因面板（简化为对照页）、批量风险扫描（延后）。

### 7.2 B 档页面（对齐问真 Tab，多两个老师工具）

> **2026-09-03 重排**：B 档成功标准已定为「老师愿意持续拿命例过来测」（§7.1）。因此本节按**回访摩擦**排优先级，不按字段完整度排。五处改动见下方标注。

1. 基本信息：姓名、乾坤造、出生地（带经纬度）、公历/农历、到分钟
   - **① 必须有快速输入**：除日期滚轮外，提供 `199303270255` 式一串数字直接输入（问真已有此设计，快一个数量级）；再加**批量粘贴**，一行一个命例。老师手上是一批盘，录入慢到第三个就不来了
   - **③ B 档不做账号**，不设登录墙。问真不登录即可排盘，只有合盘要会员。案例存 localStorage 即可
2. **基本排盘**（默认）：命主条 + 四列表格
   - **④ 第一屏顶部常驻「分歧风险」条**：本盘是否落在夏令时窗口 / 真太阳时翻转区 / 子时 / 交节 <6 小时。98% 一致是常态，如果连排十盘都与问真相同，老师就没有复访理由——这一条是我们唯一的增量
3. 专业细盘：大运流年 **二期占位**，可放五行个数示意，不断用神
4. ~~断事笔记：老师手写~~ → **② 改为结构化「老师裁定」，并入排盘页**，见 §13.2。自由备注保留一栏，但不是主体
5. **口径**抽屉：真太阳时 / 子时 / 节气说明
6. **对照**：问真口径 vs 当前口径，只高亮不同柱

表格行序（勿改，老师肌肉记忆）：

主星 → 天干 → 地支 → 藏干 → 副星 → 星运 → 自坐 → 空亡 → 纳音 → 神煞

交界预警：距时辰或节气 &lt; 15 分钟标黄。时辰不确定时，二期再做「十二时辰对照」；B 档先精确到分钟。**注意「精确到分钟」不足以表达夏令时结束日重复的那一小时，数据模型须带 `timeFold` 字段，见 §12.1。**

## 11. 分歧归因：五层拆法（2026-09-03 补）

第 3 节把「准不准」拆成天文层和口径层。实际投诉里还有三桶不在这两层内，且可能是大头。老师说「问真不准」时，下面五类混在同一句话里。

| 层 | 类别 | 典型表现 | 有无唯一答案 |
|---|---|---|---|
| L1 | 天文历法 | 夏令时未回拨、交节时刻错、纪日断链 | **有**，可证明 |
| L2 | 输入数据 | 时间来源不可靠、出生地留了默认值、公历农历混、闰月 | **有**，但错不在引擎 |
| L3 | 口径流派 | 真太阳时开关、子时两派、交节基准 | 无 |
| L4 | 神煞表 | 表源不同、同名不同算法 | 无 |
| L5 | 老师记忆或私家表 | 与任何公开表都对不上 | 无 |

拿到错例分布之前，不知道这个产品到底是什么：

- L2 占大头 → 真正的产品是客户档案与录入校验，引擎只是配件
- L4 占大头 → 护城河是「老师私家神煞表可配置」
- L5 占大头 → 需求存疑，要复核而不是加功能

### 11.1 定位：不是「更准」，是「可归因」

「更准」是不可赢的战争。L3/L4/L5 没有裁判，换一个老师我们又会「不准」。问真免费且老师已有肌肉记忆，在精度上打免费工具是错误战场。

产品职能改写为：**对已建模的历法规则（L1）、流派开关（L3）、神煞字典（L4），30 秒内定位差异源头并提供实时切换；对输入疑点（L2）给边界与闰月预警；对无法识别的差异（L5）保留自定义标注，不承诺自动归因。**

> 2026-09-03 修正：原文写「任何一次分歧 30 秒定位到哪一层」，是做不到的假承诺。L2 在数据层面完全合法（农历误选公历、地点没改默认值），软件看不出来；L5 只能得出「与已知库全不符」，再往下判就是无根据指控，反而踩了 §11.3 自己的红线。五层里只有三层能自动定位。

排盘是入场券。原列三件「问真做不到的事」，2026-09-03 实测后重新记账（依据见 §12.3）：

| # | 原列护城河 | 判定 |
|---|---|---|
| 1 | 老师/机构的口径与神煞表固化成配置 | **仍成立**。问真只有三个开关、神煞表固定不可配。但价值待验证——老师会为这个换工具吗？ |
| 2 | 机构级一致性——多位老师口径统一，卷宗可交付客户 | **仍成立，且是唯一确定的结构性差异**。问真是个人账号、个人案例库，这是它的产品形态决定的，不是疏漏 |
| 3 | 合婚与客户档案 | **作废**。问真两件都有：合盘覆盖婚恋/朋友/闺蜜/同事/领导/合伙六类关系且是**会员付费点**；记录案例带分组、星标、筛选、搜索、分类 |

第 3 条作废的连带含义：**问真认为合婚值钱（拿它收费）**。再去做一个免费的合婚，既无差异也无商业模式。

剩下能防守的两条都**不需要一个更准的引擎**——它们是形态问题（个人工具 vs 机构工具）和交付物问题，不是算法问题。这两条值不值钱，靠 §13.2 测试期问老师，不靠推断。

### 11.2 差分回归（原名「三源对账」，2026-09-03 降级）

> 2026-09-03 修正：本节原名「三源对账」，主张 `tyme4ts` / `lunar-javascript` / `sxtwl` 是三个独立裁判。**该前提不成立**——tyme4ts 与 lunar-javascript 同属 6tail 一个作者，tyme4ts 节气引自寿星，sxtwl 本身就是寿星的 C++ 移植。三者同追一个上游，三票一致只证明共享同一来源。且默认口径本就不同（lunar `sect=2`、tyme 偏 `sect=1`），归一化之后比的是配置层不是天文层。机制降级为**差分回归**，不叫独立裁判。

天文层同时跑三个实现并进 CI，比对拆到原语层，而不是只比四柱：

```
先标准化：时区 → 夏令时 → 真太阳时 → sect → 交节基准
再逐层比对：节气绝对时刻 → 儒略日 → 连续纪日 → 四柱
```

| 差分结果 | 判定 |
|---|---|
| 三源一致，与问真不同 | 有力差异证据；仍须排除输入与 L3 配置后才能归 L1 |
| 三源不一致 | 差分失败，定位到具体原语或策略，**不预判是谁的 bug** |

要真正的 L1 证据，须指定一个可追溯的权威历表当基准，而不是三票多数。工程成本：sxtwl 无官方 JS/WASM 绑定，CI 需固定 Python runner 或自行编译。

### 11.3 三条红线

- 对外不说「问真不准」。对照页只出「口径差异」「表不同」
- 分歧时不判老师错。UI 给「分歧点在 X」，不给「正确答案是 Y」
- 不为单条命例做特判迎合老师。要么改全局口径配置，要么留在归因面板

## 12. 量化事实与问真现状

### 12.1 夏令时：必须做对的入场券（原写「唯一能硬赢」，2026-09-03 降级）

中国 1986–1991 实行夏令时，出生证按当时法定钟表时记录，排盘前需回拨 1 小时。1 小时正好是时辰跨度（120 分钟）的一半。

```
1986–1991 夏令时累计生效 896 / 2191 天 = 40.9%
→ 全天全年均匀基准模型下，忽略夏令时的工具此批人 20.5% 时柱整柱错
→ 这批人 2026 年 35–40 岁
```

> **20.5% 是模型值，不是人口发生率。** 它由两个均匀假设相乘得出（出生日期跨六年均匀 × 出生时刻全天均匀）。放开日内分布后，数学上的严格区间是 0–40.9%。受影响时段是每个时辰边界后的 60 分钟（23–24、01–02、…、09–10、…），其中 **09:00–10:00 恰为择期剖宫产高峰**，故真值大概率高于 20.5% 而非低于——但没有 1986–1991 中国逐小时出生分布数据可以坐实，方向不能写成结论。
> **禁止用「每五个客户约有一个」这类话术。** 量级足以支撑「值得做对」，不足以支撑「唯一硬赢」。

这属于 L1，有唯一正确答案，不需要跟老师争流派。可作为单个错例的演示，但不是护城河（见 §12.3）。

逐年起止（切换时刻 02:00）。**1988 年起日曾被写成 4-10，错 7 天，已修正**——命理博客与部分同类产品普遍抄错 4-10：

| 年 | 起 | 止 | 源 |
|---|---|---|---|
| 1986 | 5-04 | 9-14 | 中办/国办 1986-04-12 通知 |
| 1987 | 4-12 | 9-13 | 1987-02-15 国务院公报 |
| **1988** | **4-17** | 9-11 | 京政办发〔1988〕17 号 + 人民日报 1988-04-12 |
| 1989 | 4-16 | 9-17 | IANA `Apr Sun>=11`（未见当年原文） |
| 1990 | 4-15 | 9-16 | 国办函〔1990〕16 号 |
| 1991 | 4-14 | 9-15 | IANA `Apr Sun>=11`（未见当年原文） |

国办 1987-09-09 公告的规则是「4 月中旬的第一个星期日」，中旬 = 11–20 日；1988-04-10 是上旬末，不合规则。**引擎一律用 IANA `Asia/Shanghai`，不抄命理博客。** 1992-03-03 国办发〔1992〕8 号起暂停，此后未恢复。

按错表，1988-04-10～04-16 出生者会被**我们**多减一小时、时柱整柱反错——正是我们准备用来证明别人错的那类命例。

**结束日 01:00–01:59 重复一小时，是数据模型缺陷不是回归用例。** 同一输入串对应两个瞬间（标准时 00:30 或 01:30，时支可能子可能丑），「日期 + 钟表时 + 出生地」不足以唯一表示。数据模型须加 `timeFold: first | second | unknown`；unknown 时输出双盘。

### 12.3 问真现状实测与竞品补课（2026-09-03 补）

| 夏令时 | URL `xls` | 问真真太阳时 | 四柱 |

| 关 | 0 | 09:49 | 戊辰 己未 辛未 **癸巳** |

**这怎么用：**

- 老师若勾了夏令时以为已处理，其 1986–1991 年出生客户时柱会整柱偏一位。这是 §13.2 一个可复现、可当场演示的错例来源，且与机构「2% 场景有错」的说法吻合。

- 对外只能说「同一命例两个工具结果不同，分歧点在夏令时」。**不能说问真算错了**——只测了 Web 版。

**竞品已普遍补课（2026 年公开宣称，未逐个实机）：** 参天 AI、AstroBazi、FateMaster、辰时八字、mingli-fengshui、转运盘 都做了「夏令时 + 真太阳时 + 可开关」。其中 AstroBazi 的 1988 起日同样抄了错误的 4-10。

「夏令时 + 真太阳时 + 口径可切换 + 过程可审计」这套技术四件套，在**个人向**产品里已经有人做齐。未找到面向**红娘/婚介机构**的命理引擎；婚恋 SaaS（婚恋云管家、赛信、163K、金媒）都是 CRM/配对，不含四柱引擎。

**合盘与案例库实测（同日补）：**

| 功能 | 状态 | 细节 |
|---|---|---|
| 八字合盘 | 有，**会员付费墙** | 点「开始合盘」弹「成为问真会员方可使用」。页面说明覆盖 **婚恋 / 朋友 / 闺蜜 / 同事 / 领导 / 合伙** 六类关系，「基于传统八字合盘技法，将关键的匹配要素罗列，并给出必要提示」。未注册未付费，深度只到说明层 |

### 13.1 分歧风险扫描（约半天）

前三条判据只需要出生日期时间 + 出生地经度，不需要四柱引擎；**第四条「距交节」必须求节气绝对时刻，需要历法模块或经验证的预计算表**。对老师主动拿来的盘做，标出四类风险，**只标风险不给结论**：

| 风险 | 判据 | 影响 |
|---|---|---|
| 夏令时 | 出生落在 1986–1991 夏令时窗口 | 时柱可能整柱错 |
| 真太阳时翻转区 | 偏移绝对值 > 距最近时辰边界的分钟数 | 时柱两种口径不同 |
| 子时 | 出生在 23:00–01:00 | 日柱两派不同，连累全部十神 |
| 交节 | 距交节 < 6 小时 | 月柱或年柱分歧 |

**呈现红线**：不主动批量扫老师的历史客户库。老师过去的客户已收费、有的已在交往或成婚，递上一份「你有 6 个客户排错了」的报告会被读成挑衅而非价值，第一天就断掉 §13.2 的配合。只对老师主动拿来的盘、或新盘做，措辞用「边界辅助核验」不用「排错扫描」。

### 13.2 老师裁定：产品内建，不是独立表格

> **2026-09-03 改**：原为一张让老师事后填的独立采集表。在「老师持续拿命例来测」的成功标准下，这是**产品的核心数据结构，不是配套流程**——老师每次测一个盘，产生的最有价值的东西就是「他认为哪柱对、依据什么流派」。必须在排盘页当场记，不能指望事后补表。它取代 §7.2 原第 4 项的自由备注。

排盘页每个盘可直接提交一条裁定：

| 字段 | 说明 |
|---|---|
| 分歧柱 | 年 / 月 / 日 / 时（可多选），无分歧则记「一致」 |
| 老师认为正确的干支 | 只填分歧柱 |
| 依据流派 | 下拉 + 自由填 |
| **时间来源** | 出生证 / 家人口述 / 客户自报 |
| 一句话理由 | 自由文本 |

**「时间来源」是这张表里最关键的一栏**：它是唯一能把 L2（输入本身就错）与 L1/L3（历法与口径）分开的信息，且**事后补不回来**。老师说「这盘你排错了」，若时间本身是客户自报的，那根本不是引擎的问题。

「一致」的记录同样要收——它构成 98% 的分母，没有分母就无法判断那 2% 到底是什么。

每条按 §11 五层分诊。分布出来之前不扩产品范围。
