# 轨 B 回执 · Antigravity（前端）

> **2026-09-03 集成后变更（本回执以下内容为交付当时状态，部分已被覆盖）**
>
> 产品决定：**界面不再出现任何竞品名称**。这一版就是让老师用我们的排盘、发现错误、提交正确排法。因此：
> - 对照页由「竞品口径 vs 当前口径」改为 **「未校正（按钟表时直接排）vs 当前口径」**，基准盘为三个开关全关、经度沿用当前盘。它展示的是**开关本身改了什么**，不对任何外部工具的输出做断言。

> - 界面文案、裁定表单、流派下拉、子时说明中的竞品提及全部移除。

## 1. 怎么跑起来（一条命令）

进入项目根目录后，执行以下命令即可启动本地零依赖服务：

```bash
node web/server.js
```

或者：

```bash
npm --prefix web start
```

服务将即刻启动（默认端口 `http://localhost:5173`，如被占用会自动顺延）。在浏览器中直接打开即可体验完整的朱砂卷宗细盘与老师裁定功能。

## 3. 建议引擎扩展的内容（供轨 A 参考）

1. **城市数据覆盖**：当前 `engine/src/city.js` 包含示例城市，当 Grok 轨 C 的 GeoNames 权威源全量区县合并后，建议支持地级市名与其辖区联动（如输入市名可展开下属区县）。
2. **风险量化度量**：目前 `chart.risks` 的信息很完整；如果在真太阳时跨时辰风险中增加 `boundaryDistanceMinutes`（距最近时辰边界的具体分钟数）与 `totalOffsetMinutes`，前端可以直接绘制进度刻度条，让老师一眼看清偏移了多少分钟跨界。
3. **双盘标记直通**：夏令时重复小时输出两个 `Chart` 时，建议在顶层 `chart.timeFold` 中直接标注 `'first' | 'second'`（目前在 `chart.input.timeFold` 中），便于前端直接作为主键区分。

## 4. 契约反馈（Contract Feedback）

1. **`chartId` 标准化建议**：
   契约 `Verdict` 中包含 `chartId: string`。为了便于后续对账脚本与批量回归工具自动索引，建议统一规范其生成算法，例如 `${year}${month}${day}${hour}${minute}-${city}-${gender}`。
2. **`AuditStep` 增加阶段标识**：
   目前 `chart.audit` 中的元素为 `{ step, value, note }`。若能增加可选的分类键（如 `category: 'dst' | 'solartime' | 'zishi' | 'jieqi'`），UI 在做步骤折叠或局部高亮时会更加模块化。
